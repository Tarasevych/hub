# Аудит безпеки сховища · Beveiligingsaudit

Ця навичка запускає багатоагентний аудит безпеки всього сховища й доводить його до випуску з патчами.
Сценарій: `.claude/workflows/beveiligingsaudit.js` (запуск інструментом Workflow, потрібен увімкнений режим оркестрації).

## Рішення власника, які діють завжди

1. **Сховище публічне навмисно.** Проєкт відкритий: інші люди розгортають його в себе й мають дізнатися про вразливість та отримати патч.
2. **Спершу виправити в нас, потім оприлюднити.** Патчі безпеки НЕ відправляються в сховище, доки не готовий повний випуск. Фіксації змін, опис вразливостей і архів випуску оприлюднюються одним кроком, і власник одразу встановлює оновлення. До цього моменту — лише локальні фіксації.
3. **Історія вразливостей зберігається відкрито:** після виправлення звіт двома мовами лягає в `docs/beveiliging/`, а підсумок — у `НОТАТКИ-БЕЗПЕКИ.uk.md` і `BEVEILIGINGSNOTITIES.nl.md`. Значення секретів — ніколи.
4. Аналіз лише локальний: жодних запитів до робочих сайтів `*.tarasevych.com` і жодних атак назовні.
5. Небезпечні інструменти й режими: типово «Вимкнено», але власник може обрати «Завжди»; поруч знак «!» і пояснення ризику. Дії системи й агентів — у центрі сповіщень.

## Порядок роботи

1. **Правила й завдання.** Прочитай `AGENTS.md`. Зареєструй завдання на гілці від встановленої основи:
   `node scripts/orch.mjs taak-start --id SEC-NNN --agent claude --basis <sha40> --tak fix/sec-nnn-РРРРММДД-ГГХХСС`, далі `versheid --taak SEC-NNN --fase start`.
   Наступний вільний номер — після найбільшого в `orchestratie/taken/SEC-*.json`.
2. **Середовище.** Локальний PostgreSQL 16 із тестовою базою, застосовані міграції (`npm run build:server`, потім `node dist-server/migrate.mjs` зі змінними тестів). Файл змінних тестової бази тримай поза сховищем, у робочій теці сесії.
3. **Швидкі перевірки самотужки:** `npm audit --json`; перелік останніх міграцій (перший вільний номер); видимість сховища.
4. **Запуск сценарію** інструментом Workflow, `name: "beveiligingsaudit"`, з параметрами:

   ```json
   {
     "taak": "SEC-NNN",
     "datum": "РРРРММДД",
     "klad": "<абсолютний шлях робочої теки сесії>/sec-nnn",
     "testOmgeving": "<абсолютний шлях>/test-omgeving.env",
     "basisCommit": "<HEAD на початку аудиту>",
     "eersteMigratie": 209
   }
   ```

   Кроки сценарію: **Audit** (13 перевіряльників, лише читання, знахідки з шляхом «джерело → небезпечна дія» й сценарієм атаки) → **Herstel** (групи файлів, що не перетинаються; кожну знахідку спершу відтворюють тестом `tests/eenheid/sec-nnn-<група>-<дата>.test.ts`, хибні спростовують, справжні латають мінімальним патчем) → **Toets** (три незалежні перевіряльники: обхід і повнота, регресії, інтерфейс і мова) → **Afwerking** (доопрацювання й залишки між групами).
   У хмарному контейнері одночасно працюють лише два агенти, тож повний прохід триває кілька годин.
5. **Після сценарію — сам:** перечитай знахідки й звіти; `npx tsc --noEmit`, `npm run typecheck:server`, усі `sec-*` тести, тести змінених модулів, повна збірка; звіт двома мовами в `docs/beveiliging/`; журнал розробки `orchestratie/ontwikkelarchieven/SEC-NNN.json`; `versheid --fase overdracht`.
6. **Випуск.** Робочий процес `.github/workflows/sec-nnn-uitgave.yml` за зразком `huis-001-uitgave.yml` (він сам бере за основу версію, що стоїть на сервері). Відправлення гілки запускає випуск — саме тут, одним кроком, оприлюднюються патчі. Звіт власникові: першим рядком пряме посилання на `mijn-ruimte-<versie>.tar.gz`.

## Чого не робити

- Не відправляти патчі безпеки до готового випуску (див. рішення 2).
- Не виводити значень секретів у чат, журнали, тести, фіксації.
- Не змінювати `voornaamst`, `integratie`, `release/*`, чужі гілки; не встановлювати нічого на сервер.
- Не послаблювати наявний захист заради зручності тесту.

## Офіційний плагін Claude Security

Плагін Anthropic `claude-security` (каталог `claude-plugins-official`) дає незалежний другий прохід: сканування з панеллю перевіряльників і патч-файли.
У сховище його файли НЕ покладено свідомо: ліцензія плагіна забороняє поширювати його третім особам, а це сховище публічне.

Як підключити:
- у хмарній сесії — кнопка «Додати» на картці плагіна в розмові (діє для облікового запису claude.ai; з'являється в нових сесіях);
- у терміналі Claude Code — `/plugin install claude-security@claude-plugins-official`, потім `/reload-plugins` і `/claude-security`.

Якщо плагін увімкнено, після кроку 5 запусти `/claude-security` → «Scan codebase» поверх патчів і розбери його звіт так само: відтворити тестом, залатати, перевірити.
