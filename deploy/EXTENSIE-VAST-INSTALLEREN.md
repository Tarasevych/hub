# Розширення не зникає після перезапуску Chrome

UI-011 / BUG-005 · 29.10.2026 · extensie 0.8.0

## Коротко й просто

**Чому розширення зникало.** Розширення «Mijn Ruimte» встановлюється як «розпаковане» (тека з файлами). Chrome пам’ятає лише **шлях до цієї теки**. Якщо під час запуску Chrome теки немає (її видалили, перемістили, вона була в «Завантаженнях» чи тимчасовій теці, на мережевому, USB, OneDrive або зашифрованому диску, який підключається пізніше), Chrome **мовчки прибирає розширення зі списку**. Ми перевірили це в справжньому Chrome: тека є — розширення лишається після 5 перезапусків; теки немає — після першого ж перезапуску розширення зникає повністю.

Ще одна причина: якщо завантажити пакет «діагностика» або нову версію з **іншої** теки, Chrome запам’ятовує вже нову теку (ідентифікатор той самий). Якщо цю нову теку потім видалити — розширення зникне.

**Що робити (один раз).**
1. Завантажте `mijn-ruimte-extension.zip` з сайту.
2. Запустіть у PowerShell: `powershell -ExecutionPolicy Bypass -File .\installeer-extensie-vast-windows.ps1 -Zip "$env:USERPROFILE\Downloads\mijn-ruimte-extension.zip"` — файли ляжуть у постійну теку `%LOCALAPPDATA%\MijnRuimte\extensie`.
3. `chrome://extensions` → «Режим розробника» увімкнути → «Завантажити розпаковане» → оберіть саме цю теку.
4. Оновлення: той самий скрипт у ту саму теку, потім ↻ у `chrome://extensions`. Ідентифікатор не змінюється.

Не вимикайте «Режим розробника»: Chrome тоді вимикає розпаковані розширення (але не видаляє).

**Перевірка на вашому комп’ютері (лише читає, нічого не змінює):** `powershell -ExecutionPolicy Bypass -File .\extensie-diagnose-windows.ps1` — на робочому столі з’явиться `MijnRuimte-extensie-diagnose.txt`. Там видно, з якої теки Chrome завантажував розширення, чи вона існує, на якому диску, і чи немає правил (політик), що блокують розширення.

## Технічні деталі й порівняння способів

**Причина (доведений механізм).** Розпаковане розширення існує в Chrome лише як посилання на його теку. Якщо під час запуску Chrome цієї теки немає, Chrome мовчки прибирає розширення з `chrome://extensions` (запис залишається в `Preferences`, але саме розширення зникає). Перевірено в Google Chrome 156 на Linux через справжнє «Завантажити розпаковане» у вікні вибору теки: постійна тека → присутнє після 5+ перезапусків; теку видалено → після першого ж перезапуску повністю зникає. Вимкнений режим розробника → розширення ВИМКНЕНО (`unsupportedDeveloperExtension`), але не видалено: отже, це не пояснює «повного зникнення».

Ідентифікатор стабільний: `key` прописаний у `manifest.json` → завжди `ofpffonakgjioahgfejmiblfmbkobmmi`. Друга тека з тим самим id (наприклад, пакет «diagnose» із «Завантажень») замінює реєстрацію першої теки.

**Підтримувані постійні способи у Windows (чесно):**
| Спосіб | Працює на звичайному ПК? | Примітка |
|---|---|---|
| Завантажити розпаковане з ПОСТІЙНОЇ локальної теки (`%LOCALAPPDATA%\MijnRuimte\extensie`) | так | рекомендовано; режим розробника має залишатися увімкненим |
| Власний CRX + `ExtensionInstallForcelist` (реєстр) | **ні**, якщо ПК не входить у домен AD/Entra або не зареєстрований у Chrome Enterprise Core | Визначення політики Chrome: «On Microsoft Windows instances, apps та extensions з outside  Chrome Web Store can лише be forced installed if  instance is joined to … Active Directory … Azure Active Directory or enrolled in Chrome Enterprise Core.» |
| Chrome Web Store (зокрема «приховане / unlisted») | так, після публікації | потребує акаунта розробника й перевірки; `debugger` робить перевірку суворішою |
| Перетягування CRX у `chrome://extensions` | ні | у Windows Chrome вимикає CRX не з магазину |

Скрипти: `deploy/installeer-extensie-vast-windows.ps1` (кладе файли в постійну теку; ніколи не стирає чужу теку; не чіпає Chrome і реєстр) та `deploy/extensie-diagnose-windows.ps1` (лише читання).
