## Пункт 5 — «Старий Google-обліковий запис не повинен створювати другого власника» (виконавець E)

**Вердикт: артефакт тестового середовища, НЕ помилка коду — але тепер із жорсткими запобіжниками в коді.**

Доказ. ## 4. Випуски зберігаються і доступні для завантаження; публікація на GitHub із сайту (міграція 0061)
- **Причина (доведена):** блок архівації в `deploy/uitrol/mijn-ruimte-uitrol.sh` шукав `$BRON/../<назва>` або `/tmp/<назва>`; перевірена копія називається
  `$WERK/pakket.tar.gz`, а скринька вхідних на той момент уже порожній → архів ніколи не зберігався, а оскільки крок GitHub чекав на цей архів, ніколи не створювався і випуск (останній тег від 08.10.2026).
  Тіло JSON будувалося підстановкою тексту (`"body":"${SAMENVATTING}"`): лапки або перенос рядка ламали його. Репозиторій був жорстко прописаний як `Tarasevych/hub`,
  маркер доступу у `/etc/mijn-ruimte/github-token` (ніде не задокументований). Кнопки завантаження не існувало.
- **Тепер на сервері:** перед подією `OK` root зберігає точну перевірену копію як `/srv/mijn-ruimte/pakketten/mijn-ruimte-<versie>.tar.gz` (+ `.sha256`;
  тека `root:mijnruimte 0770`, файли `0640`; помилка ніколи не фатальна) і записує `pakket_pad`, `pakket_sha256`, `pakket_bytes` у цю подію. Встановлення через SSH
  (`installeer-app.sh installeren <map>`) зберігає архів поруч із текою (`<map>.tar.gz`) або пакує вихідну теку й передає ті самі поля в `SSH_OK`.
  У root-сценарії більше немає коду GitHub і маркера доступу. Юніт застосунку отримав `ReadWritePaths=-/srv/mijn-ruimte/pakketten` (встановлювач створює теку перед перезапуском).
- **У застосунку:** `backend/uitrol-runs.ts` прив'язує архів до запуску (`app.uitrol_runs.pakket_*`; аналізатор приймає лише `/…/mijn-ruimte-<versie>.tar.gz`
  і 64-символьний hex sha256). API віддає лише «збережено / sha256 / розмір», ніколи не розкриваючи серверний шлях.
  - «Завантажити цей випуск» (деталі запуску в «Історія» та «Журнал»): `POST /api/owner/uitrol/pakket/:runId/link` (власник + сильне підтвердження
    ключ доступу/TOTP/код відновлення, 20/год) → одноразове посилання (5 хв, обліковий запис + запуск) → `POST /api/owner/uitrol/pakket/:runId` потоково віддає файл
    (білий список у `server/start.ts`, `X-Pakket-Sha256`). Оглядач перевіряє sha256 після завантаження. Обидві дії записуються в журнал (`owner.uitrol.pakket.gedownload`).
    Для запусків до цього виправлення: пояснення «архів не збережено (до виправлення 18.10.2026)» замість кнопки.
  - «Налаштування → Архіви випусків і GitHub»: який маркер доступу використовується (ціль сховища **`github-uitrol`** — технічний, лише випуски, fine-grained `Contents: write` на один репозиторій —
    має пріоритет над особистим **`github`**; показується лише назва + наявність, ніколи не значення), кнопка «Під'єднати GitHub» → «Секрети й ключі» (ключ доступу),
    репозиторій `eigenaar/repo`, «Публікувати автоматично», тека архівів (кількість, розмір) із кнопкою «Видалити старіші» (зберегти N ≥ 3 найновіших, активний — завжди; ключ доступу),
    журнал публікацій (включно з невдалими, із перекладеною причиною).
  - `backend/uitrol-github.ts`: випуск `uitrol-<versie>` зі справжнім JSON (зміни + sha256 + фіксація змін), `target_commitish` лише при 40-символьному hex `BRON-COMMIT`,
    архів як asset (потоково), ідемпотентно (наявний випуск/asset використовується повторно), 3 спроби при мережевих збоях/5xx/429, без повторів при 4xx. Помилки повертаються кодами
