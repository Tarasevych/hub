# Runbook: безпечні агенти 0.4 (розширення 0.4.0, дозволи на користувача, виправлення за аудитом)

Гілка `veilig-agenten-0.4`. Цей документ описує, що змінюється, як розгорнути це на ВМ і як перевірити, що
все працює. Розгортання самих дверей (підписані пакети, без root-шляху) описано в `RUNBOOK-VEILIGE-UITROL.md`.

## 1. Що змінюється

- **Дозволи (grants) на користувача і на пристрій.** Без чинного дозволу кожна команда відхиляється
  (`NO_GRANT`). Набори: **Спостерігач / Waarnemer** (лише читання, 30 днів), **Помічник / Helper** (також відкриття й кліки,
  кожна дія зі згодою, 7 днів), **Разово / Eenmalig** (майже все, 1 година). Окремі дозволи з тривалістю та доменами.
- **«Завжди» ('Altijd')** (без згоди на кожну дію) можливе лише після повторного підтвердження входу (посилене підтвердження), завжди має термін дії
  (стандартно 30 днів, максимум 90 — також примусово контролюється в базі даних), записується в журнал і має кнопку зупинки на сайті.
- **Деструктивні дії** (кліки/введення тексту, знімок екрана, зневаджувач/debugger, запис, виконання, Docker) вимагають свіжого
  підтвердження (дійсне 5 хвилин), крім випадків із чинним дозволом «завжди».
- **Стоп / Stop**: одним кліком відкликає всі дозволи, відхиляє команди в очікуванні, від'єднує зневаджувач і закриває
  з'єднання. Прив'язки (токени) залишаються; знову надати дозвіл можна відразу.
- **Блокування** акаунта (адміністрування) в одній транзакції відкликає токени агентів, дозволи, MCP-OAuth-токени (Claude) та
  токени `tvh_` і після цього закриває з'єднання (код 4403). Розблокування не повертає токени: потрібне повторне підключення.
- **Розширення 0.4.0**: токен більше ніколи не передається в WebSocket-URL (одноразовий квиток, 60 с), кожна команда підписана (HMAC, 120 с),
  твердження акаунта `<meta name="mjn-account">` (інший акаунт на вкладці = відмова, жовтий значок), бічна панель із кнопкою Стоп,
  діагностика лише після явного увімкнення в параметрах (буфер ≤ 200, старіші елементи зашифровані на 90 днів на сервері).
  Підключення відбувається в самому розширенні (`externally_connectable` з `mcp.tarasevych.com`); токен ніколи не потрапляє на сторінку.
- **ПК-агент 0.3.0**: жодного shell, без `-e/--eval/-c/-m` тощо, лише підписані команди, одноразовий ws-квиток.
- **MCP-консоль (аудит C2)**: дошка, токени та журнал окремо для кожного користувача в базі даних (RLS); серверні справи лише для
  власника; права лише для читання з `/etc/mijn-ruimte/mcp-rechten.json`; завантаження архіву та резервних копій лише після step-up
  через одноразовий `downloadId` (5 хвилин). Більше немає чернеток/розміщення/оновлення дверей через сайт.
- **Інші виправлення за аудитом**: H2 (режим «завжди» більше не схвалює ризиковані інструменти автоматично), H4 (step-up для
  дозволу Claude, ризикованих у режимі «завжди» та схвалення ризикованих дій), M2 (надсилання/планування пошти вимагає `mail.write`),
  M3 (результат приймається лише від того агента, який отримав команду), M4 (конектор перевіряє користувача при кожному виклику,
  токени агентів закінчуються через 30 днів).

## 2. Міграції

`0017_ai_instellingen_grants`, `0018_agent_tokens_verharding`, `0019_mcp_console_per_gebruiker`,
`0020_browser_diagnose_archief`, `0021_opdrachttypes_devtools`, після чого знову `rechten.sql`. `installeer-app.sh` виконує це
самостійно (резервна копія перед міграцією). Наявні агенти отримують 30 днів режиму «лише читання»; наявні токени отримують дату закінчення терміну дії.

## 3. На ВМ (через SSH, від імені root)

```bash
# 0. Резервна копія та пакет: див. RUNBOOK-VEILIGE-UITROL.md (підписаний пакет) або звичайне встановлення:
sudo /srv/mijn-ruimte/deploy/installeer-app.sh installeren /pad/naar/bron

# 1. Права MCP-дверей (root-файл; сайт лише читає його):
sudo install -m 0644 -o root -g root /dev/stdin /etc/mijn-ruimte/mcp-rechten.json <<'JSON'
{ "read": true, "uitrol": false }
JSON

# 2. Необов'язково: власні ключі замість TOTP_ENCRYPTION_KEY_V1 (32 байти, base64) у /etc/mijn-ruimte/geheimen.env
#    AGENT_SLEUTEL_V1=...        (запечатує ключі команд агентів)
#    AI_ARCHIEF_SLEUTEL_V1=...   (шифрує архів діагностики)
#    Увага: після зміни AGENT_SLEUTEL_V1 усі агенти потрібно підключити заново.

# 3. Перехідний період: дозволити старі агенти (токен як перше повідомлення), доки все не перейде на 0.4/0.3.0. Потім вимкнути:
#    AGENT_WS_TOKEN_AUTH_LEGACY=0   у /etc/mijn-ruimte/geheimen.env
sudo systemctl restart mijn-ruimte
journalctl -u mijn-ruimte -n 50 --no-pager
```

## 4. На ПК

1. Підписати розширення ключем на `T:\mijn-ruimte\geheim` (ніколи не на сервері):
   `node scripts/onderteken-extensie.mjs T:\mijn-ruimte\geheim\extensie.pem` → `extension/signed/*.crx` + `crx-info.json`,
   після цього `node scripts/bouw-extensie.mjs` і розгорнути цей пакет.
2. Оновити розширення до 0.4.0. Старе підключення свідомо забувається; розширення саме відкриє сторінку підключення.
   Підключіть заново на `mcp.tarasevych.com` → Агенти → Розширення браузера → **Підключити (Koppelen)**.
3. Оновити ПК-агент до 0.3.0 і підключити заново (новий код підключення, дійсний 5 хвилин). Додайте в `--allow` лише
   ті програми, які вам справді потрібні; `node`, `python`, оболонку (shells) тощо без фіксованих аргументів не додавайте.
4. Оберіть для кожного пристрою набір дозволів (типово **Спостерігач / Waarnemer**) і натисніть **Тест**.

## 5. Перевірка

- На сайті: Агенти → браузер → стан *Активний (Actief)*, **Тест** успішний, **Стоп** вимикає все одним кліком.
- Вкладка з іншим акаунтом: значок жовтий, команди відхиляються.
- `curl -i -H "Upgrade: websocket" -H "Connection: Upgrade" "https://<site>/agent/ws?token=x"` → 404 (токен в URL відхиляється).
- Модульні тести: `node scripts/eenheidstests.mjs ai-grants-contract`, `mcp-console-c2`, `stapop-h4`, `mcp-connector`,
  `browser-keten`, `browser-extensie`, `extensie-toestand`, `uitrol-deur`.

## 6. Відкат

Активувати попередній випуск (`installeer-app.sh terugdraaien`). Міграції 0017–0021 лише додають таблиці та колонки;
старіший випуск їх ігнорує. Розширення 0.4.0 потребує сервера 0.4 (ws-квиток, підписані команди): після
відкату потрібно заново встановити й підключити розширення 0.3. ПК-агент 0.3.0 зі старим сервером повертається до старого способу
входу, але відхиляє непідписані команди (якщо не задано `HUB_AGENT_ALLOW_UNSIGNED=1`).
