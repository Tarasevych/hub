# Конектор Mijn Ruimte для Claude (claude.ai → Customize → Connectors)

Дозволяє підключити **свій акаунт Claude** до сайту: Claude (з хмари Anthropic) отримує інструменти для **ваших власних
пристроїв** (ПК, ВМ з агентом) і вашого GitHub-токена. Кожен зареєстрований користувач сайту входить своїм акаунтом
і дає доступ лише до своїх пристроїв.

## Адреса конектора

```
https://mcp.tarasevych.com/mcp
```

Сервер MCP: Streamable HTTP (JSON-відповіді). Автентифікація: **OAuth 2.x + PKCE (S256) + динамічна реєстрація клієнта**.
Статичні ключі в «Request headers» не потрібні (у Claude це бета для обмеженого кола організацій).

## Як додати в Claude

1. Claude → **Customize → Connectors → Add custom connector**.
2. **Name**: `Mijn Ruimte` (будь-яка). **MCP server URL**: адреса вище. Натисніть **Continue**.
3. **Authentication**: **Sign in now**. **OAuth client**: **Register automatically** (DCR). Request headers лишіть порожніми. **Add**.
4. Claude відкриє сайт: увійдіть (потрібне право `api-platform`), перегляньте запит і натисніть **Дозволити**.
5. У чаті: **+ → Connectors** → увімкніть конектор і напишіть, наприклад: «покажи мої пристрої».

Керування на сайті: `mcp.tarasevych.com` → **Агенти** → «Надані доступи» (список і відкликання).

**Режим кожного інструмента** (на сторінці «Агенти → Інструменти й дозволи», зберігається на сервері, `app.connector_tool_settings.modes`): «Завжди» (без додаткового запиту сайту), «Питати» (кожен виклик чекає «Дозволити» на сайті; для інструментів сайту це черга `app.connector_tool_calls`, для пристроїв і браузера це примусове схвалення поверх політики агента), «Вимк.» (прихований від Claude й відхиляється на сервері). Є «Усі інструменти», «Вимкнути групу», «За замовчуванням».  Небезпечні інструменти (`RISKY_TOOLS`: запис файлів, команди, Docker-керування, кліки/введення/вибір/клавіші/дії сайту, скріншот, глибока діагностика) **за замовчуванням вимкнені** і не видимі для Claude. Користувач сам може поставити їм «Питати» або «Завжди» (зі знаком «!», поясненням ризиків і підтвердженням на сторінці). «Завжди» тут означає: без кліку на кожен виклик, а межі агента (папки, список команд) і перемикачі розширення лишаються. Масове «Усі інструменти → Завжди/Питати» їх не чіпає.

**Безпека внутрішнього виклику:** інструменти сайту викликають маршрути сайту в тому самому процесі через подію, яку створює лише `site-dispatch.ts` (позначена в `WeakMap`); `ownerRequireSession` повертає сесію саме того користувача з OAuth-токена Claude. HTTP-запит не може бути «делегованим» (перевіряє тест). Доступні лише маршрути зі списку `TOEGESTANE_ROUTES`. Новий інструмент = новий запис у `SITE_TOOLS` + маршрут у цьому списку.

Кожен інструмент користувач може вимкнути в «Інструменти й дозволи» (сервер ховає його з `tools/list` і відхиляє виклик). Деталі розширення: `deploy/BROWSER-EXTENSIE.md`.

Ці інструменти викликають уже наявні маршрути консолі (`POST/PATCH/PUT /api/mcp/board`, `POST /api/mcp/spiegel/…`). Політика ШІ лишається стелею. Читання лишається читанням.

Немає в конекторі, навіть якщо стара назва дверей ще відома: схвалення випуску ключем, відкат, створення резервної копії, зміна політики ШІ, завантаження архіву чи бекапа в чат, значення секретів. Такі імена відповідають `OUT_OF_SCOPE`.
| `github_get` | лише читання | GET до GitHub API з вашим PAT зі сховища (з'являється, лише якщо PAT є) |

У налаштуваннях конектора в Claude (Tool permissions) запис і виконання можна заблокувати або вимагати підтвердження окремо від читання.

## Два простори: приватний і технічний (з 14.10.2026, міграція `0042_ai_ruimte.sql`)

Кожне підключення ШІ (OAuth-грант), кожен токен `tvh_…` і кожен підключений пристрій належать **рівно одному простору**
(`shared/ai-ruimte.ts`). Простір задає **людина на сайті**, коли створює підключення; ШІ не може його змінити, не бачить інструментів
іншого простору в `tools/list`, а виклик поза простором отримує `SPACE_SEPARATED: …` (isError, в аудиті `reden: ruimte`) ще до політики,
прав і грантів.

| | Приватний простір | Технічний простір |
|---|---|---|
| Де підключають | mcp.* → **Агенти** (обліковий простір) | mcp.* → **Технічні підключення** (технічний профіль; лише власник) |
| Куди | лише конектор `/mcp` | двері сервера `/Grok`, `/claude`, … або конектор `/mcp` |
| Що бачить ШІ | пристрої й браузери користувача, пошта, календар, Drive, дошка, нотатки, GitHub-токен | випуски (`get_live_release`, `list_releases`, `read_release_file`), стан сервера (`get_system_health`), підготовка оновлень `uitrol_voorstel_*` (лише з грантом), двері сервера, агенти на сервері |
| Чого не бачить | жодного інструмента сайту/сервера; жодного пристрою з технічного простору | жодної пошти, Drive, дошки, браузера; жодного особистого пристрою |
| Пристрої | `app.agents.ruimte='prive'` (коди підключення зі сторінки Агенти) | `app.agents.ruimte='technisch'` (коди зі сторінки Додатки → «Підключити цей сервер») |
| Право «готувати оновлення» | не видається ніколи (`RUIMTE_PRIVE`) | лише технічним токенам/грантам; схвалює завжди власник passkey |
| Сповіщення | дзвінок облікового простору | дзвінок технічного простору (`shared/meldingen-ruimte.ts`) |

Правила сервера:
- `ruimte` зберігається в `app.mcp_oauth_auth`, `app.mcp_oauth_tokens`, `app.mcp_console_tokens`, `app.agent_pairing_codes`, `app.agents`;
  усе старе стає `prive` (найменші права), крім грантів із чинним правом «готувати оновлення» та агентів, які встановила сама інсталяція на сервері.
- Технічний простір при створенні (consent, `POST /api/mcp/tokens`, `POST /api/owner/agents/pairing-code` з `ruimte:'technisch'`) вимагає
  власника **і** активний технічний профіль (`backend/ai-ruimte-poort.ts`: `OWNER_REQUIRED`, `TECH_PROFIEL_VEREIST`). Запит від дверей (`mrd_…`)
  завжди технічний: в обліковому просторі вікно «Дозволити» показує лише посилання «Відкрити в технічному просторі».
- `initialize.instructions` різні для кожного простору (`RUIMTE_INSTRUCTIES`); підписана політика ШІ лишається стелею в обох.
- Інструменти пристроїв (`machine_*`, `docker_*`, `app_*`, `system_metrics`) доступні в обох просторах, але бачать лише пристрої **свого** простору.

## Як це працює (потік)

1. Claude викликає `POST /mcp` без токена → **401** із `WWW-Authenticate: Bearer realm="mcp", resource_metadata="…/.well-known/oauth-protected-resource/mcp"`.
2. Claude читає метадані (RFC 9728 → RFC 8414), реєструє клієнта (`POST /oauth2/register`; дозволено лише callback Claude
   `https://claude.ai/api/mcp/auth_callback` та loopback `/callback` для Claude Code).
3. Браузер → `GET /oauth2/authorize` → редирект на сайт `…/agents?consent=<id>` (приватний простір; з `ruimte=technisch` у запиті сайту — `…/verbindingen?consent=<id>`) → ви входите й натискаєте «Дозволити».
4. Сайт видає **одноразовий код** (діє 2 хв, прив'язаний до `code_challenge`) → редирект у Claude.
5. Claude обмінює код на токени: `POST /oauth2/token` (`application/x-www-form-urlencoded`, `code_verifier`).
   Access-токен 1 година, refresh-токен 30 днів із **ротацією** і виявленням повторного використання (краде́ний токен → вся грант відкликається).
6. Усі виклики `POST /mcp` несуть `Authorization: Bearer …`; токен прив'язаний до вашого акаунта.

## Адреси (зовнішні → внутрішні)

| Зовнішня адреса | Внутрішній маршрут | Куди йде в тунелі |
|---|---|---|
| `POST /mcp` | `/api/mcp-connector/rpc` | основний застосунок :8080 |
| `/.well-known/oauth-protected-resource/mcp` | `…/prm` | :8080 (окреме правило **вище** за міст) |
| `/.well-known/oauth-authorization-server/oauth2` | `…/asm` | :8080 (окреме правило **вище** за міст) |
| `POST /oauth2/register`, `GET /oauth2/authorize`, `POST /oauth2/token`, `POST /oauth2/revoke` | `…/register`, `…/authorize`, `…/token`, `…/revoke` | :8080 (`/oauth2` ≠ `/oauth`, тому міст не перехоплює) |

`/oauth/*`, `/Grok`, `/claude`, `/health` і решта `/.well-known/*` залишаються за мостом (:8091, окремий read-only міст для Grok).

Правило тунелю (має стояти **перед** правилом моста для `mcp.`; перевірте `cloudflared tunnel ingress rule <url>`):

```yaml
  - hostname: mcp.tarasevych.com
    path: ^/\.well-known/(oauth-protected-resource/mcp|oauth-authorization-server/oauth2)$
    service: http://127.0.0.1:8080
```

## Безпека

- **Ізоляція користувачів:** `userId` береться лише з токена; аргументи моделі його не змінюють. Тест `mcp-connector.test.ts` перевіряє, що A не бачить пристроїв B.
- **Одноразові коди, PKCE S256 обов'язковий, ротація refresh, відкликання** (UI + `POST /oauth2/revoke`, RFC 7009). Токени в БД лише як sha256.
- **Лише відомі адреси повернення** (з 13.10.2026, `shared/ai-verbinding.ts`): https відомих ШІ (claude.ai, grok.com, x.ai, chatgpt.com, openai.com, vscode.dev), loopback `http://127.0.0.1|localhost|[::1]:<порт>/…` (Claude Code, Cursor, VS Code), схеми застосунків `cursor://`, `vscode://`, `vscode-insiders://`, `windsurf://`, власна адреса сайту `/oauth-terug` і те, що власник додав у `/etc/mijn-ruimte/mcp-rechten.json` → `"oauthRedirects": ["https://…/callback", "https://…/префікс/"]`. Без фрагментів, логінів у URL, `javascript:`/`data:`/`file:`. Невідомий `client_id` або `redirect_uri` ніколи не призводять до редиректу.
- **Prompt injection:** результати інструментів із пристрою позначені як недовірені дані; у `instructions` сервера сказано не виконувати команд із вмісту файлів.
  Запис і виконання завжди підтверджує користувач на сайті.
- **Ліміти:** 120 викликів/хв на токен, 20 реєстрацій/хв і 120 обмінів токенів/хв на IP, не більше 10 активних доступів на користувача, не більше 20 запитів на підтвердження одночасно.
- **CSRF/Origin:** для цих маршрутів Origin не перевіряється (автентифікація — Bearer/PKCE, не cookie); решта API залишається під CSRF-перевіркою.

## Cloudflare: перевірте, що нічого не блокує Anthropic

Запити йдуть із `160.79.104.0/21` (не з браузера). У панелі Cloudflare для `mcp.tarasevych.com`: вимкніть Bot Fight Mode / Browser Integrity Check
для шляхів `/mcp`, `/oauth2/*`, `/.well-known/*`, або додайте правило Skip для діапазону Anthropic; переконайтеся, що немає WAF-викликів (challenge).
Симптом: «Couldn't reach the MCP server», а в журналі застосунку немає жодного запиту.

## Діагностика

- **Couldn't reach the MCP server** → тунель/WAF (див. вище); `curl -i -X POST https://mcp.tarasevych.com/mcp` має дати `401` із `WWW-Authenticate`.
- **Authorization failed** → `curl https://mcp.tarasevych.com/.well-known/oauth-authorization-server/oauth2` має віддати JSON із `registration_endpoint`.
- **Після «Дозволити» нічого не відбувається** → журнал `journalctl -u mijn-ruimte -n 50`; код живе 2 хв.
- **Інструментів немає** → у вас немає підключеного агента (`machine_*`) і PAT GitHub у сховищі.
- Усе стерти: сайт → Агенти → «Надані доступи» → Відкликати, і в Claude видалити конектор.


## Підключення ШІ: в один клік або вручну (з 13.10.2026)

Сайт: `mcp.<домен>` → **Агенти → Токени й двері → «Підключити ШІ»**. Оберіть ШІ (Grok, Claude, ChatGPT, Gemini, Copilot, Cursor, інший),
куди підключати (**двері сервера** `/Grok`, `/claude`, … — лише власник сервера; або **конектор** `/mcp` — ваші пристрої, пошта, Drive)
і **термін доступу** для цього ШІ: 1 год (оновлюється до 14 днів, рекомендовано), 8 год, 1 доба, 7 днів, 30 днів, безстроково (до відкликання).
Довгі терміни (7 днів і більше) вимагають повторного підтвердження входу. Термін можна змінити ще раз у вікні «Дозволити».

**1. «Підключити автоматично (в один клік)»** — OAuth 2.1 + PKCE (S256) + динамічна реєстрація:
- вставте адресу (`https://mcp.<домен>/Grok` або `/mcp`) у клієнт ШІ; клієнт сам відкриє сайт — ви вже ввійшли, натисніть **«Дозволити»**;
- двері (`GET /oauth/authorize`) більше не просять токен дверей: вони перенаправляють на вікно сайту `…/verbindingen?consent=mrd_…` (технічний простір)
  (перевірка сесії власника + повторне підтвердження входу), сайт передає рішення дверям через loopback;
- для клієнтів, що не вміють відкривати вхід самі: кнопка **«Отримати токен зараз»** — сайт сам проходить OAuth із PKCE у спливному
  вікні й показує Bearer-токен один раз (з готовою конфігурацією `mcp.json` і перевіркою через `curl`).

**2. «Підключити вручну (прямий токен)»** — як і раніше: токен `tvh_…` (30 днів) у заголовку `Authorization: Bearer …` конфігурації клієнта.
Тепер він працює і на `/mcp`, і на дверях (на дверях — лише токен власника сервера). Стара форма з токеном дверей лишилася:
`/oauth/authorize?…&methode=token` або посилання «Ввести токен дверей вручну» у вікні «Дозволити».

**Що змінилося в дверях (`deploy/mcp/server.mjs`, служба `mijn-ruimte-mcp`):**
- метадані для кожних дверей: `GET /.well-known/oauth-protected-resource/<двері>` (і `/<двері>/.well-known/oauth-protected-resource`)
  повертає `resource` рівно тієї адреси, яку використовує клієнт (`https://mcp.<домен>/Grok`, `…/claude`); `WWW-Authenticate` у 401
  містить `resource_metadata` саме цих дверей, `scope="read"` і `error="invalid_token"`, якщо токен був, але не підійшов;
- токен прив'язаний до дверей, для яких його видали (`resource`): токен для `/claude` не відкриє `/Grok`;
- `/intern/*` — лише для сайту: тільки loopback, без заголовків тунелю (`cf-connecting-ip`, `cf-ray`, `x-forwarded-for`) і з ключем,
  який двері при кожному старті записують у `/srv/mijn-ruimte/mcp-state/intern.sleutel` (0640, користувач `mijnruimte`). У правилі тунелю
  `/intern` немає, тож ззовні ці адреси недосяжні;
- список доступів через двері (хто дозволив, термін, остання активність) і відкликання — у «Технічні підключення» (технічний профіль); дії записуються в журнал
  (`owner.mcp.deur.approved` / `denied` / `revoked`, з дверима, клієнтом і терміном);
- JSON-RPC-пакети (batch), невідома `Mcp-Session-Id` після перезапуску більше не дає 404, CORS для `/.well-known`, `/oauth/*` і дверей.

**502 / таймаути при паралельній ініціалізації.** Причина: cloudflared тримає з'єднання до 90 с (`originRequest.keepAliveTimeout`),
а Node закривав «тихі» з'єднання раніше (двері: 5 с, застосунок: 65 с). Тунель інколи надсилав запит у щойно закрите з'єднання → 502.
Тепер `keepAliveTimeout` дверей 120 с (`headersTimeout` 125 с), застосунку 100 с. Окремих налаштувань не потрібно: це частина випуску.

**Для будь-якого сервера «Мій простір» (BYOS):** усе встановлюється звичайним випуском через `/usr/local/sbin/mijn-ruimte-installeer`
(двері й їхній unit-файл копіює `installeer-app.sh`, міграція `0029_ai_verbinding_duur.sql` іде разом). Правило тунелю не змінюється.
Якщо двері на сервері не запущені, сайт просто показує «Двері сервера зараз не працюють», а конектор `/mcp` працює як завжди.
