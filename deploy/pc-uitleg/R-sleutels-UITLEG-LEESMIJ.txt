ЩО ЛЕЖИТЬ У ЦІЙ ТЕЦІ
1. herstelsleutel-age.txt  - СЕКРЕТНИЙ ключ відновлення (age, приватний ключ).
   Тільки ним можна розшифрувати резервні копії бази, файлів і секретів сервера.
   Створений 03.10.2026 на цьому ПК. Доступ має лише користувач t.
2. herstelsleutel-age.pub.txt - ПУБЛІЧНА частина цього ключа (починається з "age1...").
   Не секрет. Сервер (VM) нею тільки ЗАШИФРОВУЄ. Розшифрувати нею не можна.
3. mijn-ruimte-webserver - СЕКРЕТНИЙ SSH-ключ для входу на сервер (VM) як "beheer".
   Це запасна копія ключа з T:\mijn-ruimte\hulpmiddelen\ssh\. Доступ лише для t.
4. mijn-ruimte-webserver.pub - публічна частина SSH-ключа. Не секрет.

НАВІЩО ЦЕ ПОТРІБНО
- Сервер щоночі робить резервну копію і одразу шифрує її публічним ключем.
  Навіть якщо хтось вкраде копію, без herstelsleutel-age.txt він нічого не прочитає.
- Але й ВИ без цього ключа нічого не прочитаєте. Втратили ключ = втратили всі копії.
- SSH-ключ потрібен, щоб керувати сервером і забирати резервні копії.

ЧИ ПОТРІБНО ЦЕ ЗБЕРІГАТИ?  ТАК, обов'язково обидва секретні ключі.

ЯК ЗБЕРІГАТИ БЕЗПЕЧНО
- Зробіть ще 1-2 копії herstelsleutel-age.txt ОФЛАЙН: на USB-флешку, яка лежить
  у шухляді/сейфі (не постійно в ПК), і/або роздрукуйте на папері (3 рядки тексту).
- НІКОЛИ не надсилайте ключ поштою, у месенджері, не кладіть у хмару
  (Google Drive, OneDrive), у GitHub, на сервер (VM) або на диск T:\.
- Не показуйте вміст файлу на екрані при інших людях і не робіть знімків екрана.
- Не змінюйте права доступу до файлу (зараз: тільки користувач t).

ЯКЩО КЛЮЧ ВТРАЧЕНО
- Старі резервні копії більше НЕ можна розшифрувати.
- Створіть нову пару ключів (age-keygen), покладіть новий публічний ключ на сервер
  у /etc/mijn-ruimte/backup-ontvanger.age.pub, зробіть новий архів секретів і нову копію.
ЯКЩО КЛЮЧ ВИКРАДЕНО АБО ВИПАДКОВО ОПУБЛІКОВАНО
- Негайно: нова пара ключів (як вище), видаліть старі зашифровані копії там, де їх
  міг узяти чужий, і ЗМІНІТЬ усі секрети сервера (geheimen.env, ключ тунелю Cloudflare),
  бо їх можна було розшифрувати з архіву секретів.
- SSH-ключ втрачено/викрадено: створіть новий SSH-ключ, впишіть його публічну частину
  в /home/beheer/.ssh/authorized_keys на сервері і видаліть звідти старий.

ЯК ЦЕ ПРАЦЮЄ ПРИ ВІДНОВЛЕННІ
- Див. HERSTEL.md у корені R:\mijn-ruimte-reservekopie\ та T:\mijn-ruimte\.
- Коротко: код з GitHub -> новий сервер -> на ПК розшифровуємо цим ключем архів
  секретів і резервну копію -> через SSH одразу передаємо на новий сервер.
  Ключ залишається тільки на ПК і ніколи не копіюється на сервер.

WAT STAAT IN DEZE MAP
1. herstelsleutel-age.txt - GEHEIME herstelsleutel (age-privesleutel). Alleen hiermee
   kun je de back-ups van database, uploads en servergeheimen ontsleutelen.
   Gemaakt op 03-10-2026 op deze pc. Alleen gebruiker t heeft toegang.
2. herstelsleutel-age.pub.txt - de PUBLIEKE helft (begint met "age1..."). Niet geheim.
   De server (VM) gebruikt die alleen om te VERSLEUTELEN; ontsleutelen kan er niet mee.
3. mijn-ruimte-webserver - GEHEIME SSH-sleutel om als "beheer" op de server in te loggen.
   Reservekopie van T:\mijn-ruimte\hulpmiddelen\ssh\. Alleen gebruiker t heeft toegang.
4. mijn-ruimte-webserver.pub - publieke helft van de SSH-sleutel. Niet geheim.

WAAROM BESTAAT DIT
- De server maakt elke nacht een back-up en versleutelt die meteen met de publieke sleutel.
  Wie een back-up steelt, kan zonder herstelsleutel-age.txt niets lezen.
- Maar JIJ ook niet: sleutel kwijt = alle back-ups onbruikbaar.
- De SSH-sleutel is nodig om de server te beheren en back-ups op te halen.

IS HET NODIG?  JA, beide geheime sleutels zijn onmisbaar.

VEILIG BEWAREN
- Maak 1-2 extra OFFLINE kopieen van herstelsleutel-age.txt: een USB-stick die in een
  la/kluis ligt (niet steeds in de pc) en/of een papieren afdruk (3 regels tekst).
- NOOIT mailen, via chat sturen, in de cloud (Google Drive, OneDrive), in GitHub, op de
  server (VM) of op T:\ zetten.
- Niet tonen op een scherm waar anderen meekijken; geen schermafbeeldingen.
- Laat de toegangsrechten zoals ze zijn (nu: alleen gebruiker t).

SLEUTEL KWIJT
- Oude back-ups zijn dan NIET meer te ontsleutelen.
- Maak een nieuw sleutelpaar (age-keygen), zet de nieuwe publieke sleutel op de server in
  /etc/mijn-ruimte/backup-ontvanger.age.pub, maak een nieuw geheimenarchief en een nieuwe back-up.
SLEUTEL GESTOLEN OF PER ONGELUK GEDEELD
- Direct: nieuw sleutelpaar (zie boven), oude versleutelde kopieen verwijderen waar een
  ander erbij kon, en ALLE servergeheimen vervangen (geheimen.env, Cloudflare-tunnelsleutel),
  want die waren met de gelekte sleutel uit het geheimenarchief te halen.
- SSH-sleutel kwijt/gestolen: nieuwe SSH-sleutel maken, publieke helft in
  /home/beheer/.ssh/authorized_keys op de server zetten en de oude daar verwijderen.

ROL BIJ HERSTEL
- Zie HERSTEL.md in R:\mijn-ruimte-reservekopie\ en T:\mijn-ruimte\.
- Kort: code uit GitHub -> nieuwe server -> op de pc met deze sleutel het geheimenarchief
  en de back-up ontsleutelen -> via SSH meteen naar de nieuwe server. De sleutel blijft
  alleen op de pc en gaat nooit naar de server.
