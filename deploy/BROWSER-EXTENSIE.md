# Розширення браузера «Mijn Ruimte»

Дозволяє вашому ШІ-помічнику (Claude через наш MCP-конектор) читати відкриті сторінки сайту й виконувати дії в них. Працює **лише** на `*.tarasevych.com`.

## Як це працює

```
Claude ──MCP──▶ mcp.tarasevych.com ──черга команд (політика/«Дозволити»)──▶ WSS /agent/ws ──▶ розширення ──▶ вкладка сайту
```

- Розширення це звичайний агент із `platform = 'browser'` (та сама таблиця `agents`, ті самі токени, ізоляція й схвалення, що й у агента ПК).
- Можливості (14 типів команд, міграції 0012–0014; список в `backend/browser-capabilities.ts` = `extension/shared.js`, збіг перевіряє тест):
  - Читання й перегляд: `snapshot`, `diagnostics`, `tabs`, `scroll`, `wait`.
  - Навігація: `navigate`, `history` (назад, вперед, оновити).
  - Дії на сторінці: `click`, `type`, `select`, `key` (лише навігаційні клавіші), `invoke` (дії, які пропонує сайт).
  - Розширені: `screenshot` (JPEG; повертається як MCP-зображення), `deep_diagnostics` (з 0.3.3 без `chrome.debugger`: на кілька секунд у сторінку вбудовується пасивний збирач `diag-hook.js` через `chrome.scripting`; додаткових дозволів і банера не потрібно. Chrome не дозволяє `debugger` як необов'язковий дозвіл — запит завжди завершувався помилкою «Only permissions specified in the manifest may be requested»).
- Кожну можливість користувач вмикає/вимикає **окремо для кожного браузера** перемикачем із поясненням «?» (що буде, якщо ввімкнути й вимкнути). Додатковий перемикач «без підтвердження» є лише для читання/перегляду й навігації. За замовчуванням увімкнено лише читання й перегляд.
- Тип команди перевіряє CHECK у БД, мож­ливість — `policy.enabled` на сервері (`browserGate`), адресу — і сервер, і розширення (`isOwnSiteUrl`).
- Політика за замовчуванням: увімкнено й без підтвердження лише читання й перегляд. Кліки, введення, вибір, клавіші, дії сайту, знімок екрана й глибока діагностика **не можуть** бути автоматичними (сервер відхиляє такий запит).
- Вміст сторінки для моделі позначається як недовірений (`untrusted()`), поля пароля/оплати розширення не читає й не заповнює.
- Налаштування інструментів (вимкнути окремий інструмент) зберігаються на сервері (`app.connector_tool_settings`), а не лише в інтерфейсі.

## Активація і вхід в акаунт (захист від чужого використання)

Розширення **нічого не робить**, поки виконано обидві умови (перевіряє сервер, а не розширення):

1. **Користувач увімкнув цей браузер** перемикачем «Дозволити ШІ користуватися цим браузером» у кабінеті (`agents.browser_enabled`). Після підключення браузер завжди **вимкнений**.
2. **Ввійшов в акаунт на сайті:** відкрита сторінка сайту з активною сесією кожні 2 хв надсилає підтвердження (`POST /api/owner/agents/:id/heartbeat`, вимагає чинну сесію й права). Сервер продовжує `armed_until` на 5 хв. Вихід із акаунту, закриття сайту чи прострочена сесія → за кілька хвилин браузер знову «заблокований».

Що це дає:
- Підключити розширення може лише той, хто ввійшов в акаунт (одноразовий код на 10 хв видається лише з кабінету).
- Викрадений токен розширення (шкідливе ПЗ) нічого не дасть без чинної сесії: підтвердження не підробити.
- Вже схвалена команда не піде в розширення, якщо підтвердження встигло прострочитись (`dispatchCommand`), і обхідного шляху через `submitCommand` немає.
- Відкликання браузера (`Відключити`) закриває канал одразу (код 4403).
- Усі кроки (підключення, увімкнення/вимкнення, схвалення) пишуться в загальний аудит.

## Діагностика без `chrome.debugger`

`browser_get_diagnostics` читає короткий журнал самого сайту (`src/ai-site-actions.ts`): помилки JS, `console.error/warn`, невдалі запити (лише метод, шлях без query і статус) і метрики сторінки. Дозвіл `chrome.debugger` (CDP) свідомо **не** використовується: він дає доступ до всього трафіку вкладки, показує банер «розширення налагоджує браузер» і суперечить принципу мінімальних прав. Глибший аналіз (`deep_diagnostics`) виконує вбудований на кілька секунд збирач `diag-hook.js` (лише консоль, винятки, адреса/статус/час запитів; ніколи вміст чи заголовки).

## Дії сайту: реєстр і хук

Компоненти реєструють свої дії хуком `useMcpContext(context, actions)` (`src/use-mcp-context.ts`) → з'являються в `browser_snapshot` → `actions` як `<context>_<id>`. Читання `window.__MCP_CONTEXT__` (лише опис, без функцій) доступне для розробників. Базові дії: `list_services`, `open_service`, `get_page_metrics`, `get_diagnostics`. Дії, що змінюють дані (резервна копія, режим обслуговування тощо), реєструються лише там, де така функція справді є на сайті, і завжди проходять `browser.invoke` із підтвердженням.

## Встановлення: помічник, автоматичне відкриття сторінки активації, вхід

Chrome не дозволяє встановити розширення поза магазином без участі користувача, тому реалізовано максимум автоматизації:
1. Сайт сам визначає ОС і пропонує **помічник-файл**: `Install-MijnRuimte.cmd` (Windows) або `install-mijn-ruimte.sh` (macOS/Linux). Він завантажує ZIP з нашого сайту, **перевіряє SHA-256** (сума вшита під час збірки), розпаковує в окрему папку профілю (без прав адміністратора), кладе шлях у буфер обміну й відкриває `chrome://extensions`. Користувачу лишається ввімкнути «Режим розробника» і вибрати папку.
2. Одразу після встановлення розширення **саме відкриває** `mcp.tarasevych.com/agents?extension=welcome`. Якщо користувач не ввійшов, спершу вхід; прапорець привітання зберігається через вхід (`src/extension-welcome-store.ts`). Далі майстер: розширення знайдено → ви ввійшли → підключити → обрати можливості → увімкнути для ШІ.
3. Вікно розширення підказує, що робити: «Увійти й підключити на сайті», «Увімкнути на сайті», «Увійти на сайті» (коли сесії немає), «ШІ активний». Стан бере з сервера за власним токеном (`POST /api/owner/agents/self`).
4. Справжній «в один клік»: публікація в Chrome Web Store, див. `deploy/CHROME-WEB-STORE.md` (кнопка на сайті з'явиться після запису URL у `extension/store-url.txt`).

## Варіант CRX (власний підписаний пакет)

Крім помічника й ZIP, на сторінці є кнопка «Завантажити CRX»: підписаний CRX3 (`/downloads/mijn-ruimte-extension.crx`) та `updates.xml` для автооновлення (`update_url` у маніфесті цього пакета).

**Чесно про обмеження:** ChatGPT та інші ставляться «.crx одним кліком», бо файл іде з Chrome Web Store з підписом Google. Chrome на Windows і macOS **відхиляє CRX не з магазину** («Пакет недійсний», `CRX_REQUIRED_PROOF_MISSING`), це захист Chrome. Наш CRX приймають деякі Chromium-браузери, Linux, та комп'ютери, де адміністратор дозволив розширення політикою `ExtensionInstallForcelist` (на Windows поза доменом/керуванням Chrome це теж блокує). Тому основний шлях лишається помічник або (після публікації) Chrome Web Store.

Як це працює й підтримується:
- Підпис своїм ключем: `node scripts/sign-extension.mjs` (лише локально). Ключ: `T:\mijn-ruimte\geheim\extension-signing-key.pem` (створюється, якщо немає; **не в репозиторії**; зробіть резервну копію: без нього не можна випускати оновлення під тим самим id).
- Результат (публічний, у репозиторії): `extension/signed/mijn-ruimte-extension.crx` і `crx-info.json` (id розширення, версія, `contentHash`).
- `npm run build` публікує CRX **лише якщо** підпис дійсний, а `contentHash` збігається з поточними файлами розширення. Змінили код розширення або версію → знову `node scripts/sign-extension.mjs`, закомітити `extension/signed/`. Застарілий CRX збірка не віддає (і пише про це).
- Тест `browser-extensie.test.ts` перевіряє: дійсний підпис, id з ключа, відповідність `updates.xml`, актуальність вмісту, відсутність приватного ключа, і що зміна одного байта ламає підпис.
- Не перевірено на справжньому Chrome (формат CRX3 реалізовано за специфікацією Chromium; перевірте встановлення на Linux/Chromium або через політику).

## Встановлення вручну (розробка / власне використання)

1. mcp.tarasevych.com → Агенти → «Розширення браузера» → «Завантажити розширення» (`/downloads/mijn-ruimte-extension.zip`).
2. Розпакувати в окрему папку. Chrome/Edge: `chrome://extensions` → «Режим розробника» → «Завантажити розпаковане».
3. Оновити сторінку Агенти й натиснути «Підключити до мого облікового запису» (код підключення передається розширенню автоматично, вручну нічого вводити не треба).
4. Увімкнути перемикач «Дозволити ШІ користуватися цим браузером» (за замовчуванням вимкнено).

Для звичайних користувачів потрібна публікація в Chrome Web Store (Chrome не дозволяє ставити сторонні розширення поза магазином). Це робить власник сайту зі своїм акаунтом розробника. Збірка пакета: `node scripts/build-extension.mjs` (входить у `npm run build`).

## Дії сайту для ШІ

`src/ai-site-actions.ts`: сторінка відповідає на `window.postMessage` (лише від самої сторінки) і, якщо браузер підтримує WebMCP, реєструє ті самі дії в `navigator.modelContext`. Зараз: `list_services` (читання) і `open_service` (навігація всередині сайту).

- `tests/eenheid/browser-extensie.test.ts` — спільні правила й пакет (ZIP, маніфест без широких прав).

- Не перевірено автоматично: робота в справжньому Chrome (потрібне ручне встановлення).
