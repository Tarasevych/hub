# Розширення браузера «Mijn Ruimte»

Дозволяє вашому ШІ-помічнику (Claude через наш MCP-конектор) читати відкриті сторінки сайту й виконувати дії в них. Працює **лише** на `*.tarasevych.com`.

## Як це працює

```
Claude ──MCP──▶ mcp.tarasevych.com ──черга команд (політика/«Дозволити»)──▶ WSS /agent/ws ──▶ розширення ──▶ вкладка сайту
```

- Розширення це звичайний агент із `platform = 'browser'` (та сама таблиця `agents`, ті самі токени, ізоляція й схвалення, що й у агента ПК).
- Команди: `browser.snapshot`, `browser.navigate`, `browser.invoke`, `browser.click`, `browser.type`. Тип команди перевіряє CHECK у БД (міграція 0012), адресу — і сервер, і розширення (`isOwnSiteUrl`).
- Політика за замовчуванням: **лише `browser.snapshot` без підтвердження**. «Відкривати сторінки без підтвердження» вмикається окремо для кожного браузера. Кліки, введення та дії сайту **не можуть** бути автоматичними (сервер відхиляє такий запит до політики).
- Вміст сторінки для моделі позначається як недовірений (`untrusted()`), поля пароля/оплати розширення не читає й не заповнює.
- Налаштування інструментів (вимкнути окремий інструмент) зберігаються на сервері (`app.connector_tool_settings`), а не лише в інтерфейсі.

## Активація і вхід в акаунт (захист від чужого використання)

Розширення **нічого не робить**, поки виконано обидві умови (перевіряє сервер, а не розширення):

1. **Користувач увімкнув цей браузер** перемикачем «Дозволити ШІ користуватися цим браузером» у кабінеті (`agents.browser_enabled`). Після підключення браузер завжди **вимкнений**.
2. **Ввійшов в акаунт на сайті:** відкрита сторінка сайту з активною сесією кожні 2 хв надсилає підтвердження (`POST /api/owner/agents/:id/heartbeat`, вимагає чинну сесію й права). Сервер продовжує `armed_until` на 5 хв. Вихід із акаунту, закриття сайту чи прострочена сесія → за кілька хвилин браузер знову «заблокований».

Що це дає:
- Підключити розширення може лише той, хто ввійшов в акаунт (одноразовий код на 10 хв видається лише з кабінету).
- Викрадений токен розширення (шкідливе ПЗ) нічого не дасть без чинної сесії: підтвердження не підробити.
- Вже схвалена команда не піде в розширення, якщо підтвердження встигло прострочитись (`dispatchCommand`), і обхідного шляху через `submitCommand` немає.
- Відкликання браузера (`Відключити`) закриває канал одразу (код 4403).
- Усі кроки (підключення, увімкнення/вимкнення, схвалення) пишуться в загальний аудит.

## Діагностика без `chrome.debugger`

`browser_get_diagnostics` читає короткий журнал самого сайту (`src/ai-site-actions.ts`): помилки JS, `console.error/warn`, невдалі запити (лише метод, шлях без query і статус) і метрики сторінки. Дозвіл `chrome.debugger` (CDP) свідомо **не** використовується: він дає доступ до всього трафіку вкладки, показує банер «розширення налагоджує браузер» і суперечить принципу мінімальних прав. Якщо знадобиться глибший аналіз, його можна додати окремо як необов'язковий дозвіл.

## Дії сайту: реєстр і хук

Компоненти реєструють свої дії хуком `useMcpContext(context, actions)` (`src/use-mcp-context.ts`) → з'являються в `browser_snapshot` → `actions` як `<context>_<id>`. Читання `window.__MCP_CONTEXT__` (лише опис, без функцій) доступне для розробників. Базові дії: `list_services`, `open_service`, `get_page_metrics`, `get_diagnostics`. Дії, що змінюють дані (резервна копія, режим обслуговування тощо), реєструються лише там, де така функція справді є на сайті, і завжди проходять `browser.invoke` із підтвердженням.

## Встановлення (розробка / власне використання)

1. mcp.tarasevych.com → Агенти → «Розширення браузера» → «Завантажити розширення» (`/downloads/mijn-ruimte-extension.zip`).
2. Розпакувати в окрему папку. Chrome/Edge: `chrome://extensions` → «Режим розробника» → «Завантажити розпаковане».
3. Оновити сторінку Агенти й натиснути «Підключити до мого облікового запису» (код підключення передається розширенню автоматично, вручну нічого вводити не треба).
4. Увімкнути перемикач «Дозволити ШІ користуватися цим браузером» (за замовчуванням вимкнено).

Для звичайних користувачів потрібна публікація в Chrome Web Store (Chrome не дозволяє ставити сторонні розширення поза магазином). Це робить власник сайту зі своїм акаунтом розробника. Збірка пакета: `node scripts/build-extension.mjs` (входить у `npm run build`).

## Дії сайту для ШІ

`src/ai-site-actions.ts`: сторінка відповідає на `window.postMessage` (лише від самої сторінки) і, якщо браузер підтримує WebMCP, реєструє ті самі дії в `navigator.modelContext`. Зараз: `list_services` (читання) і `open_service` (навігація всередині сайту).

## Перевірка

- `tests/eenheid/browser-extensie.test.ts` — спільні правила й пакет (ZIP, маніфест без широких прав).
- `tests/eenheid/browser-keten.test.ts` — вся ланцюжок із тестовим клієнтом протоколу: пряме читання, схвалення/відмова, автонавігація, відхилення чужих адрес, ізоляція користувачів, відкликання (4403).
- Не перевірено автоматично: робота в справжньому Chrome (потрібне ручне встановлення).
