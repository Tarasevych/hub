# UI-014 «Звірка / Розвиток продукту» (Afstemming vNext) — 30.10.2026

Прапорець: `afstemming-vnext` (міграція `0197` — лише рядок прапорця). УВІМК → нова картотека на
api.tarasevych.com/afstemming; ВИМК → стара «Матриця фактичної реалізації» без жодних змін (її 25 тверджень
тепер живуть в одному джерелі `backend/waarheid-claims.ts`, звідки читають і стара сторінка, і міграція).
Сторінка лишається за технічним профілем, нових канонічних вкладок немає — жодних змін реєстрів.

## Що це
Жива картотека розвитку продукту за ТЗ UI-014: один ідентифікатор супроводжує задум через весь цикл
«захоплено → … → підтверджено на робоче середовище → прийнято», з чесним розділенням «код написано / розгорнуто /
працює / власник прийняв». Вісім розділів: Огляд, Картотека, Мапа зв'язків, Перевірки, Випуски, Можливості,
Історія, Джерела.

## Ключові властивості
- **Дві осі стану**: життєвий етап і фактична придатність — не взаємозамінні; прогрес лише лічильниками (AC n/m),
  жодних вигаданих відсотків.
- **Append-only історія**: події не змінюються й не зникають; ревізії з diff будь-яких двох; optimistic-захист
  версій (409 з показом свіжої картки — нічого не затирається мовчки).
- **Докази — єдиний шлях угору**: критерій стає «passed» лише з доказом; `production_verified` — лише з
  робоче середовище-доказом; `accepted` — лише після production_verified; агент може пропонувати й додавати докази,
  але не схвалювати (AGENT_MAG_NIET).
- **25 застарілий спадок-claims** мігрують автоматично з provenance «waarheid-matrix-26.10.2026» і БЕЗ підвищення
  доказовості (confirmed без QA → чесне «невідомо»).
- **Три шляхи додавання**: текст (сирий задум зберігається), файл .json/.md/.txt з попереднім переглядом,
  ідемпотентністю (повторний імпорт не створює дубля) і списком схожих; агентський HTTP-API (voorstel/bewijs/
  koppel stel-voor) з аудитом актора.
- **Зв'язки і конфлікти**: 11 типів; кандидати (лексика+граф) — лише пропозиції, без auto-злиття; рішення
  власника пишеться як Besluit + подія.
- **Випуски**: читаються лише для читання з реальної історії встановлень (app.uitrol_runs); прив'язка карток;
  постфлайт чесно каже «розгорнуто ≠ підтверджено», регресії окремо. Нічого тут не розгортає.
- **Статичний інвентар**: вкладки/прапорці/маршрути самого сайту проти карток → «функція без картки»
  (одним натисканням — чернетка) і «картка без сліду».
- **Можливості**: довідник для людини; «перевірено» лише з робоче середовище-доказом (або застарілий спадок-огляд власника).
- **Мапа зв'язків**: SVG-граф (детерміноване розкладання, зум/пан/фільтри, клавіатурний доступ), мінікартка →
  перехід у деталь без втрати контексту.
- Двомовність uk/nl, 320–1440 px світла/темна, нижня панель на телефоні, деталі на весь екран.

## Чесно не зроблено (позначено в UI як «заплановано»)
MCP-обгортки `afstemming.*` (агентський шлях сьогодні — HTTP-API картотеки); семантичний пошук схожості
(зараз лексика+граф); аналіз diff випуску для «незареєстрованих змін» (поле є, чесно порожнє); живі
лише для читання-проби робоче середовище; ШІ-розбір тексту ідеї (структуру задає людина); аудіо/відео/зображення в імпорті;
повна стрічка подій усіх карток одним запитом (зараз: останні події + повна історія будь-якої картки).

## Тести
Юніт 266 (kern 68, koppel 61, ui 74, zvirka 63) + **наскрізні 44/44** (сценарії §14 ТЗ: прапорець, застарілий спадок-25 без
промоції, ідея→картка, імпорт із попередній перегляд та ідемпотентністю, ревізія+diff+409, конфлікт+рішення власника,
доказ-пропускні бар'єри критеріїв і фаз, реальний випуск+постфлайт «не підтверджено», граф, скан→чернетка, можливості
«не перевірено», звіт без відсотків, історія, nl, 5×2 розмірів/тем) — стабільно 3 прогони поспіль.
Регресія: cloud 50/50, huis 49/49, notities 39/39, agenda 101/101; всі ворота складання ok; tsc базові 3/20.
