# Розширення не зникає після перезапуску Chrome

UI-011 / BUG-005 · 29.10.2026 · extensie 0.8.0

## Коротко й просто

**Чому розширення зникало.** Розширення «Mijn Ruimte» встановлюється як «розпаковане» (папка з файлами). Chrome пам’ятає лише **шлях до цієї папки**. Якщо під час запуску Chrome папки немає (її видалили, перемістили, вона була в «Завантаженнях» чи тимчасовій папці, на мережевому, USB, OneDrive або зашифрованому диску, який підключається пізніше), Chrome **мовчки прибирає розширення зі списку**. Ми перевірили це в справжньому Chrome: папка є — розширення лишається після 5 перезапусків; папки немає — після першого ж перезапуску розширення зникає повністю.

Ще одна причина: якщо завантажити пакет «діагностика» або нову версію з **іншої** папки, Chrome запам’ятовує вже нову папку (ідентифікатор той самий). Якщо цю нову папку потім видалити — розширення зникне.

**Що робити (один раз).**
1. Завантажте `mijn-ruimte-extension.zip` з сайту.
2. Запустіть у PowerShell: `powershell -ExecutionPolicy Bypass -File .\installeer-extensie-vast-windows.ps1 -Zip "$env:USERPROFILE\Downloads\mijn-ruimte-extension.zip"` — файли ляжуть у постійну папку `%LOCALAPPDATA%\MijnRuimte\extensie`.
3. `chrome://extensions` → «Режим розробника» увімкнути → «Завантажити розпаковане» → оберіть саме цю папку.
4. Оновлення: той самий скрипт у ту саму папку, потім ↻ у `chrome://extensions`. Ідентифікатор не змінюється.

Не вимикайте «Режим розробника»: Chrome тоді вимикає розпаковані розширення (але не видаляє).

**Перевірка на вашому комп’ютері (лише читає, нічого не змінює):** `powershell -ExecutionPolicy Bypass -File .\extensie-diagnose-windows.ps1` — на робочому столі з’явиться `MijnRuimte-extensie-diagnose.txt`. Там видно, з якої папки Chrome завантажував розширення, чи вона існує, на якому диску, і чи немає правил (політик), що блокують розширення.

## Технічні деталі й порівняння способів

**Причина (доведений механізм).** Розпаковане розширення існує в Chrome лише як посилання на його папку. Якщо під час запуску Chrome цієї папки немає, Chrome мовчки прибирає розширення з `chrome://extensions` (запис залишається в `Preferences`, але саме розширення зникає). Перевірено в Google Chrome 156 на Linux через справжнє «Завантажити розпаковане» у вікні вибору папки: постійна папка → присутнє після 5+ перезапусків; папку видалено → після першого ж перезапуску повністю зникає. Вимкнений режим розробника → розширення ВИМКНЕНО (`unsupportedDeveloperExtension`), але не видалено: отже, це не пояснює «повного зникнення».

Ідентифікатор стабільний: `key` прописаний у `manifest.json` → завжди `ofpffonakgjioahgfejmiblfmbkobmmi`. Друга папка з тим самим id (наприклад, пакет «diagnose» із «Завантажень») замінює реєстрацію першої папки.

**Підтримувані постійні способи у Windows (чесно):**
| Спосіб | Працює на звичайному ПК? | Примітка |
|---|---|---|
| Завантажити розпаковане з ПОСТІЙНОЇ локальної папки (`%LOCALAPPDATA%\MijnRuimte\extensie`) | так | рекомендовано; режим розробника має залишатися увімкненим |
| Власний CRX + `ExtensionInstallForcelist` (реєстр) | **ні**, якщо ПК не входить у домен AD/Entra або не зареєстрований у Chrome Enterprise Core | Визначення політики Chrome: «On Microsoft Windows instances, apps and extensions from outside the Chrome Web Store can only be forced installed if the instance is joined to … Active Directory … Azure Active Directory or enrolled in Chrome Enterprise Core.» |
| Chrome Web Store (зокрема «приховане / unlisted») | так, після публікації | потребує акаунта розробника й перевірки; `debugger` робить перевірку суворішою |
| Перетягування CRX у `chrome://extensions` | ні | у Windows Chrome вимикає CRX не з магазину |

Скрипти: `deploy/installeer-extensie-vast-windows.ps1` (кладе файли в постійну папку; ніколи не стирає чужу папку; не чіпає Chrome і реєстр) та `deploy/extensie-diagnose-windows.ps1` (лише читання).
