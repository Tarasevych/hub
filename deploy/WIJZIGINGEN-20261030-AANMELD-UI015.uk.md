# UI-015 «Способи входу» (Aanmeldmethoden vNext) — 30.10.2026

Прапорець: `aanmeldmethoden-vnext` (міграція `0198` — лише рядок прапорця, вимкнено). УВІМК → нова
сторінка id.tarasevych.com/aanmeldmethoden (вкладка «Способи входу»); ВИМК → стара форма без жодних змін.
Вкладки «Безпека» та «Відновлення» в обох станах лишаються на наявній формі — глибокі посилання
(#aanmeldmethoden-2fa, …-herstel, …-passkeys, …-sleutelkluis, …-google) працюють і відкривають деталь.

## Що це

Повне переосмислення сторінки за ТЗ UI-015: hero-банер без вигаданих цифр, згруповані картки методів
(Вхід / Passkey / Захист / Доступ іншим) з одною головною дією на картці, пошук і фільтри-чипи, контекстні
деталь-панелі (бічна панель на широкому екрані, весь екран на телефоні) і чесний каталог майбутніх
провайдерів. Нуль змін у механізмах безпеки: та сама контролер-логіка (`ToegangslaagWeergave`), ті самі
API-маршрути, step-up, lockout-захист, шифрування.

## Ключові властивості

- **УІ ніколи не вигадує стан**: кожна картка — з /api/owner/access/snapshot або живого статус-маршруту;
  «Підключено» без підтвердження сервера не існує; відсотків захисту немає.
- **Наявні потоки перевикористано**: passkeys, герстелькоди, TOTP, пароль, sleutelkluis, довірені пристрої,
  сесії — ті самі компоненти секцій всередині деталь-панелей; TOTP-секрет видно лише в деталі.
- **Останній робочий шлях входу захищено** від вимкнення — з поясненням на картці (beschermd).
- **Справжні контури нових провайдерів (бекенд уже в коді, вмикається ключами власника)**:
  - Microsoft, Discord: OAuth2 code потік + PKCE S256, одноразовий стан (TTL 10 хв, спалюється ДО обміну),
    перевірка id_token підписом із JWKS (iss/aud/exp/nonce) або /users/@me;
  - Telegram: Login Widget із серверною перевіркою HMAC-SHA256 і свіжості auth_date (≤10 хв);
  - Apple: клієнтський секрет = ES256-JWT із p8-ключа (потрібен платний Apple Developer);
  - прив'язка ЛИШЕ до вже увійшлого акаунта (жодних нових акаунтів через ці шляхи), мітки масковані,
    аудит кожного кроку, rate-limit.
- **Правило відображення (ТЗ §4) дотримано**: кнопка «Підключити» з'являється лише коли сервер каже
  klaarVoorKoppeling (усі ключі власника наявні ТА самотест контуру пройдено). До того картка чесно
  показує список ПОТРІБНИХ ключів (лише назви, ніколи значення) і стан самотесту.
- **Чесні межі**: вхід ЧЕРЕЗ нове підключення (видача сесії) — заплановано (зараз: прив'язка як додатковий
  спосіб); WhatsApp — неможливо (немає публічного consumer-login API, картка це каже прямо, з обхідним
  шляхом); SMS — заплановано (потрібен платний провайдер розсилання). Жодних монограм-підробок логотипів.
- **Адаптивність**: 320–1920, перевірено на 7 ширинах × світла/темна, без горизонтального скролу;
  деталь на ≤599px відкривається на весь екран (портал у body, scroll-lock, фокус-пастка, Esc).

## Нові маршрути (усе під сесією власника, фіксований перелік сервісів)

- POST /api/owner/aanmeld/vnext/aanbieders — живий стан 6 провайдерів (ключі-назви, самотест, гекоппельд).
- POST /api/owner/aanmeld/vnext/zelftest { id } — лише для читання самотест власного контуру + аудит.
- POST /api/owner/aanmeld/vnext/start { id } — authorize-URL (або параметри віджета Telegram); 409 без
  klaarVoorKoppeling.
- GET /api/aanmeld/koppel/:aanbieder/terug — колбек: стан+PKCE / HMAC / id_token → прив'язка + подія.
- POST /api/owner/aanmeld/vnext/ontkoppel { id } — відв'язати (з step-up, останній шлях не чіпається).

Колекції: `aanmeld_koppelingen_v1` (ownerUserId, aanbieder, subject, маскована мітка),
`aanmeld_states_v1` (одноразові стан, TTL), `aanmeld_zelftest_v1`. Ключі середовища:
AANMELD_MICROSOFT_CLIENT_ID/_CLIENT_SECRET, AANMELD_DISCORD_CLIENT_ID/_CLIENT_SECRET,
AANMELD_TELEGRAM_BOT_TOKEN/_BOT_NAAM, AANMELD_APPLE_CLIENT_ID/_TEAM_ID/_KEY_ID/_PRIVATE_KEY
(+ AANMELD_<ID>_BASIS і AANMELD_TERUG_BASIS лише для тестових середовищ).

## Тести

- Юніт: aanmeld-koppel-20261030 (64) — повні контури проти нагобудованого провайдера (PKCE, JWKS, ES256,
  HMAC, антиповтор стан, маскування); aanmeld-ui-20261030 (105) — мапер карток, контракт, чесність станів.
- E2E aanmeldmethoden-vnext (37): прапорець вимк/увімк; чесні картки; деталі зі справжніми секціями;
  TOTP start→confirm→disable через СПРАВЖНІЙ step-up-діалог (RFC-6238 у тесті, антиреплей сервера
  шановано); каталог без кнопки до самотесту; повний цикл підключення Microsoft із доказом PKCE;
  пошук/групи; nl; 7 розмірів × 2 теми; нуль несподіваних помилок.
- Регресія на цій базі: afstemming 44, cloud 50, huis 49, notities 39, agenda 101 — зелено.
