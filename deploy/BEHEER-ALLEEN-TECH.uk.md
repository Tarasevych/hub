# Адмін-права лише в активному технічному профілі (етап B)

**Навіщо.** Якщо хтось викраде звичайну сесію (навіть власника чи адміністратора), адмін-консоль йому нічого не дасть:
адмін-дія виконується лише з **активного технічному профілі в цій самій вкладці**, з правом, яке потрібне саме для цієї дії.

**Стан після встановлення:** перемикач **ВИМКНЕНО**. Сайт працює як раніше, а OPA лише рахує в тіні, що змінилося б.

## Яке право потрібне для якої дії
| Адмін-дія | Потрібне право технічного профілю | Ролі, що його мають |
|---|---|---|
| перегляд консолі (`admin.read`) | будь-який активний профіль | усі |
| користувачі (`users.manage`), каталоги (`directories.manage`) | `users.manage` | Адміністратор, Власник |
| ролі (`roles.manage`) | `roles.delegate` | Адміністратор, Власник |
| журнал (`audit.read`) | `journaal.lezen` | Адміністратор, Аудитор, Власник |
| пристрої (`devices.read`) | `diagnose.lezen` | усі, крім Аудитора |
| застосунки, SSO (`apps.manage`, `sso.manage`) | `diensten.beheren` | Адміністратор, Власник |

Таблиця збігається з `deploy/opa/beleid/data.json` (`doel_tech`); тест `beleid-afdwingen` тримає сайт і OPA однаковими.

## Коли вмикати
Технічний профіль (Адміністратор або Власник) → «Щось не працює? Перевірка» → «Правила (OPA)»:
- «Служба працює»;
- **«Розбіжність» = 0** — сайт і OPA вирішують однаково;
- **«Без тех. профілю» ≈ 0** протягом кількох днів — ви звикли вмикати технічний профіль перед адмін-роботою.

## Увімкнути (на сервері, як beheer)
```bash
sudo systemctl status mijn-ruimte-opa            # служба має працювати (127.0.0.1:8181)
sudo nano /etc/mijn-ruimte/mcp-rechten.json      # додати або змінити: "beheer-alleen-tech": true
```
Сайт читає файл раз на 10 секунд; перезапуск не потрібен. Лише булеве `true` вмикає перемикач: текст `"true"` вважається вимкненим.

## Що змінюється, коли увімкнено
- Без активного технічного профілю в цій вкладці адмін-консоль показує: «Адмін-права діють лише в активному технічному профілі…».
- Якщо OPA не відповіла (800 мс), адмін-дію **відхилено** («Служба правил (OPA) не відповіла…»). Це навмисно: fail-closed.
- Кожна така відмова записується в журнал («Агенти → Журнал», розділ «Доступ»).
- Звичайні функції сайту (пошта, файли, ШІ) **не змінюються**: йдеться лише про адмін-консоль.

## Вимкнути або аварійно повернути доступ
```bash
sudo nano /etc/mijn-ruimte/mcp-rechten.json      # "beheer-alleen-tech": false
# або, якщо винна OPA:
sudo systemctl restart mijn-ruimte-opa
```
Сайт сам цей перемикач змінити не може, і прапорець функції теж: перемикає лише root на сервері.

## Чому так
- Право в момент дії, а не «назавжди» (just-in-time): викрадена сесія без технічного профілю нічого не дає.
- Два незалежні вирішувачі (правило сайту й OPA), і обидва мають дозволити. Помилка в одному не відкриває доступ.
- Fail-closed лише для адмін-консолі; відновлення — одна правка root-файлу, без нового випуску.
