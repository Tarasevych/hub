# Розширення оглядача: оновлення

Станом на 18.10.2026 (аудит, пункт 9)

**Що було.** Код розширення на сайті мав версію 0.4.0, а опублікований підписаний пакет (CRX) — 0.3.4. Складання (`scripts/bouw-extensie.mjs`) правильно не публікувала застарілий CRX, але й не казала чому; сайт не показував, що є нова версія. Сценарій підпису мовчки створював **новий** ключ, якщо старого не було поруч — це дало б інший ідентифікатор розширення, і всі наявні встановлення більше ніколи не отримали б оновлення.

**Що тепер.**
- Версія розширення — **0.4.1** (команда `UPDATE_CHECK`, власна перевірка версії, значок «↑»). Мінімальна робоча версія — **0.4.0** (`shared/extensie-update.ts`, `EXT_MIN_VERSIE`; одне джерело для сайту і складання).
- `extension-version.json` тепер містить `minVersion`, `crxStatus` (`actueel` / `verouderd` / `ontbreekt` / `ongeldig`) і `ondertekendeVersie`. Застарілі `mijn-ruimte-extension.crx` і `updates.xml` з попередньої складання видаляються, щоб Chrome не «оновив» до старої версії.
- На кожній сторінці сайту, коли розширення старіше за опубліковане, з'є смуга **«Доступне оновлення розширення X → Y»**:
  - **«Оновити автоматично»** — лише якщо розширення встановлене з нашого CRX (у маніфесті є `update_url`) і опублікований CRX новіший. Розширення просить Chrome перевірити оновлення (`chrome.runtime.requestUpdateCheck`) і перезапускається. Нічого не встановлюється без натискання.
  - **«Як оновити вручну»** — кроки для «Завантажити розпаковане»: завантажити zip, замінити файли в тій самій теці, у `chrome://extensions` натиснути ↻.
  - **«Нагадати пізніше»** — ховає на 24 години. Для обов'язкового оновлення (нижче 0.4.0) цієї кнопки немає.
- Саме розширення раз на 6 годин читає `https://mcp.tarasevych.com/downloads/extension-version.json` і показує «↑» на значку з підказкою.

**Що потрібно від власника (одноразово, на ПК з ключем).** Ключ підпису не лежить у репозиторії (і не повинен). Щоб автоматичне оновлення запрацювало для 0.4.1:
```
node scripts/onderteken-extensie.mjs T:\mijn-ruimte\geheim\extension-signing-key.pem
```
Сценарій перевіряє, що ключ дає той самий ідентифікатор `ofpffonakgjioahgfejmiblfmbkobmmi`; інакше нічого не записує (exit 3). Без ключа — exit 2 і пояснення. Новий ключ — лише свідомо: `--nieuwe-sleutel` (тоді наявні встановлення оновлення не отримають). Після підпису — новий пакет: `extension/signed/*` потрапить у складання, з'являться `crx` і `updates.xml`, `crxStatus: actueel`.

Хто зараз має 0.3.4 з CRX: Chrome оновить сам, щойно буде опубліковано CRX 0.4.1 (`update_url` у старому пакеті вказує на той самий `updates.xml`). Хто має «розпаковане» 0.4.0: смуга покаже ручні кроки.
