# Конектори ШІ v2: окрема адреса для кожного агента (етап 1, 15.10.2026)

> **Оновлено 20.10.2026 — етап 2 виконано.** Адреси тепер короткі: `https://mcp.tarasevych.com/<агент>` (`/claude`, `/gpt`,
> `/grok`, `/gemini`, `/copilot`, `/cursor`). Старі `/ai/<агент>` відповідають **308 Permanent Redirect** на короткі (308, а не
> 301/302: MCP працює через POST, і 301/302 дозволяє клієнту перетворити його на GET). Права більше не закарбовуються в грант:
> один конектор показує і приватні, і технічні інструменти, а що саме доступно — вирішується в момент кожного виклику за
> поточним станом користувача. Усе про розгортання: **`deploy/CONNECTOR-EEN-PAD.md`**. Нижче — опис етапу 1; де написано
> `/ai/<агент>`, читайте `/<агент>`.

- **Назви інструментів нідерландською** (`shared/connector-v2/catalogus.ts`):
  `<суть, ≤5 слів>_<агент>_<піддомен>[_<сервіс>]_tarasevych_com_<gebruiker|beheer>`.
  Наприклад: `lezen_bericht_grok_mail_gmail_tarasevych_com_gebruiker`, `tonen_live_release_gpt_admin_tarasevych_com_beheer`.
  - Лише `a-z`, `0-9` і `_`, не довше 64 знаків: цього вимагають Claude, ChatGPT і специфікація MCP. Тому в назві `creeren`, а на
    екрані «creëren». Тест перевіряє кожну назву для кожного агента.
  - Сервіс пропускається, якщо він збігається з піддоменом (`…_github_tarasevych_com_…`, а не `…_github_github_…`).
  - Ваш приклад `creëren_nieuw_bestand_grok_mail_gmail_…` став `creeren_bestand_grok_cloud_gdrive_tarasevych_com_gebruiker`:
    створення файла стосується Диска (cloud/gdrive), а не пошти, і так назва вміщається в 64 знаки для всіх агентів.
- **Простори**:
  - `_gebruiker` — приватний простір: ваша пошта, файли, дошка, ваші пристрої;
  - `_beheer` — технічний доступ: сайт і сервер, лише власник з активним технічним профілем.
  - Пристрої й додатки є в обох просторах: `_gebruiker` означає ваш ПК, `_beheer` означає сам сервер.
  - Простір, у якому виконується виклик, визначає позначка в назві інструмента. Тому дозвіл `_beheer` ніколи не спрацює в
    приватному просторі, і навпаки.
- **Дозволи для кожного інструмента** (`app.connector_v2_rechten`):
  - **Типово** увімкнено лише безпечне: читання, низький ризик, нечутливі дані, приватний простір. Пошта, запис і
    видалення типово вимкнені.
  - **Режими** для групи, для простору чи для всього: усі дії / лише читання / читання й запис / лише запис / жодної.
  - Окремий перемикач для кожного інструмента, вмикання й вимикання категорії, пошук.
  - Шар скоупів (0044) сервер оновлює автоматично, щоб він відповідав вибраним інструментам.

## Під'єднання (вікно з кроками на mcp.*/agents)
1. **Підтвердження**: хто просить доступ, адреса повернення, адреса конектора. Якщо клієнт назвався іншим агентом, ви побачите
   попередження.
2. **Захист** — лише якщо ви ввімкнули «Додаткове підтвердження кожного нового під'єднання». Тоді знадобиться passkey або код із
   застосунку. Якщо ви щойно увійшли, додаткових кроків немає. Звичайне підтвердження входу (H4) працює як і раніше.
3. **Обліковий запис**: поточний обліковий запис або «Під'єднати інший обліковий запис». Після входу запит збережеться.
4. **Простір** (лише власник): приватний, технічний або обидва. Для технічного потрібен активний технічний профіль у цій вкладці.
5. **Дозволи**:
   - групи з піктограмами;
   - перемикач у кожного рядка має колір і значок (✓ увімкнено, × вимкнено, гайковий ключ для технічного доступу, будівельний
     бар'єр для «у розробці»);
   - кожен рядок має позначки ризику, а підсумок показує найвищий ризик у вашому виборі;
   - розгорнутий рядок показує, що робить інструмент, що це означає для вас, на що звернути увагу, схему «ШІ → дія → де» й адресу
     інструмента з кнопкою копіювання;
   - пункти «у розробці» видно, але увімкнути їх не можна.
   - Під час перепід'єднання є три розділи: «Буде додано», «Вже було», «Не буде додано». Рішення можна змінити прямо там.

## Керування (вкладка «Конектори»)
Вкладка є на mcp.*/agents, а при активному технічному профілі — на mcp.*/verbindingen.
- Для кожного агента видно адресу з кнопкою копіювання, під'єднання, кількість дозволів і їхній ризик.
- Кнопки: «Дозволи», «Перепід'єднати», «Відкликати».
- **Обмеження діє одразу** для всіх активних під'єднань цього агента. Це безпечний напрям.
- **Розширення** запам'ятовується й чекає на перепід'єднання:
  1. ви натискаєте «Перепід'єднати»;
  2. сайт закриває під'єднання;
  3. ШІ-клієнт отримує 401 і сам відкриває вікно згоди;
  4. у вікні видно, що зміниться;
  5. ваш вибір не губиться, доки ви не підтвердите.
- **Відкликання** одразу закриває доступ. Щоб працювати далі, під'єднайте агента знову.

## Що лишилося як було
- Старий конектор `https://mcp.tarasevych.com/mcp` і двері сервера (`/Grok`, `/claude`, …) працюють як раніше. Вже під'єднані ШІ

- Підписана політика ШІ, перемикачі сайту, підготовка оновлень і їхнє схвалення passkey лишаються стелею. Конектор v2 проходить
  ті самі ворота, що й `/mcp`.

## Після встановлення (як beheer)
```bash
scp mijn-ruimte-<sha>.tar.gz mijn-ruimte-<sha>.tar.gz.sha256 beheer@<сервер>:/tmp/
ssh beheer@<сервер>
cd /tmp && sha256sum -c mijn-ruimte-<sha>.tar.gz.sha256
mkdir -p ~/releases && tar -xzf mijn-ruimte-<sha>.tar.gz -C ~/releases
sudo /usr/local/sbin/mijn-ruimte-installeer installeren ~/releases/hub-<sha>
```
Міграція 0045 запускається сама. Перевірка: `curl -sI https://mcp.tarasevych.com/ai/claude -X POST` має повернути `401`
і `WWW-Authenticate` з `…/ai/claude/.well-known/oauth-protected-resource`.

**Необов'язково** (cloudflared, root-конфіг). Щоб клієнти, які спершу пробують стандартний шлях
`/.well-known/oauth-protected-resource/ai/<агент>`, знаходили метадані одразу, перше правило для mcp у
`/etc/cloudflared/config.yml` можна замінити рядком із шаблону `deploy/cloudflared-config.yml`:
```
    path: ^/\.well-known/(oauth-protected-resource/(mcp|ai/(claude|gpt|grok|gemini|copilot|cursor))|oauth-authorization-server/oauth2)$
```
Потім виконайте `sudo systemctl restart cloudflared`. Без цієї зміни все теж працює: відповідь 401 одразу вказує правильну адресу.
