# Робочий стіл — Блоки (блок у блоці), вільні розміри та місця

> **Коротко для Власника.** Зараз розмір значків у «Швидкому доступі» та інших вікнах обчислюється автоматично від ширини вікна, а значки самі переносяться в рядки. Новий режим «Блоки» дозволить: для кожного значка окремо задати місце, розмір, колір, форму, підпис; ставити значки в ряд, колонкою, сіткою або вільно; робити «блок у блоці» з власними розмірами; перетягувати значки між блоками, на робочий стіл, у меню або на сторінку. Усе за прапорцем `werkblad-blokken`, він спершу вимкнений, і тоді все працює точно як зараз. «Авто» лишається стандартом для кожного параметра, а кнопка «Скинути» повертає авто. Від вас потрібні 3 рішення (внизу), для кожного є рекомендація.

## 2. Модель

- **Блок (`Blok`)** = контейнер з `indeling` (режим `vrij` | `rij` | `kolom` | `raster`; проміжок, внутрішній відступ, вирівнювання за головною/поперечною віссю, перенесення, напрямок, колонки сітки або `auto`) та `kinderen`.
- **Елемент (`Onderdeel`)** = один доступний для натискання об'єкт (`itemId` з реєстру; ціль завжди береться з реєстру, ніколи не довільна URL-адреса).
- Кожен вузол: `afmeting` (ширина/висота як `auto` | `px` | `procent` | `deel`, плюс мін./макс.), `positie` (лише у `vrij`), `volgorde`, `rasterSpan`, `uiterlijk` (колір фону, значка, тексту, рамки як токен теми або `#rrggbb`; товщина рамки, форма, радіус, прозорість, тінь), `apparaten` (показувати/ховати для комп'ютера/планшета/телефону), `vergrendeld`.
- Додатково для елемента: `icoon` (розмір, стиль, id замінного значка), `label` (показувати так/ні/авто, місце знизу/праворуч/зверху/ліворуч, розмір, власний текст).
- Додатково для блоку: `standaardOnderdeel` = стиль для всіх дочірніх елементів без власного значення (один натискання «усі значки 48px»).
- Глибина макс. 4, макс. 60 елементів на блок, цикл неможливий (`beoordeelNeerzetting` → `kring`).
- **Стандартом усюди є `auto`** = точно поточні правила обчислення CSS (клітинка 84px, значок 36→28px). Контракт: `shared/werkblad-blokken.ts`.

### Місця (`Plek`)
`Plek` = де щось може стояти: `canvas`, `blok`, `menu`, `pagina` (секція на сторінці), `zijbalk`, `werkbalk`. Кожне місце визначає, що воно приймає (елемент/блок/блок інтерфейсу), макс. глибину/кількість і дозволені розміри (меню = лише малий). Перетворення: елемент → полотно (`canvas`) стає звичайним ярликом (стиль зберігається); елемент → меню стає пунктом меню (через наявні налаштування меню, лише елементи з реєстру); технічні елементи дозволені лише в технічному просторі.

### Перетягування (drag & drop)
- Миша: старт після 5px. Дотик/стилус: довге натискання 450мс (як у `menu-slepen.ts`). Esc = скасувати, Alt/Ctrl = копія.
- Під час перетягування: цільове місце підсвічується; недопустиме місце показує причину текстом («Тут не можна: блок не можна покласти сам у себе»).
- Клавіатура (рівноцінна альтернатива): вибрати елемент → «Перемістити в…» → список місць → стрілки для порядку → Enter. Жодних нативних браузерних `prompt`.
- Скасувати/повторити: одна історія на шар пристрою (макс. 50), також між різними місцями; Ctrl+Z / Ctrl+Shift+Z і кнопки.

### Сховище, міграція, повернення стану
- WerkbladV3 залишається `v:3`; додається необов'язкове поле `blok?: BlokInhoud` у `DesktopEntry` (блок інтерфейсу або тека).
- Міграція 0116: колонка `blok jsonb NULL` у `app.werkblad_items`, плюс місця меню/сторінок у новій таблиці `app.werkblad_plekken` (RLS, та сама версія на шар і 409 `WERKBLAD_V3_VEROUDERD`).
- Ліниве перетворення: блок інтерфейсу без `blok` перетворюється лише під час першого редагування (`blokUitWidget`, `bron:'widget-standaard'`). Теки залишаються теками, доки не отримають другий рівень; `mapUitBlok` повертає теку без втрат.
- Прапорець вимкнено → колонка ігнорується (не стирається), старе подання. Повернення стану до старого випуску → старий код не читає колонку; **ризик**: старий код перезаписує елементи (`DELETE`+`INSERT`) і тоді втратив би `blok` → потік A перед кожним записом зберігає копію у `werkblad_v3_lade.blokken_backup`, а кнопка «Відновити блоки» повертає її назад.
- Сервер валідує тією самою `valideerBlok` (ліміти, формат кольору, `itemId` з реєстру, простір).

## 3. Панель властивостей
Невелика бічна панель (на телефоні: нижній аркуш) поруч із виділенням; вкладки «Розмір», «Вигляд», «Розташування», «Пристрої». Кожна опція: зрозуміла українська назва, пояснення (?), живий попередній перегляд, «Скинути» для кожної властивості (повернення до авто). Зверху пресети: «Автоматично (як зараз)», «Великі значки», «Компактний ряд», «Колонка», «Вільно». Одиниці виміру завжди видимі («пікселів», «% ширини блоку», «частка вільного місця»). Кожна дія показує «Зберігаю…» → «Збережено» або зрозумілу помилку з кнопкою «Спробувати знову».

## 4. П'ять основних сценаріїв (натискання за натисканням)
1. **Значки більші:** «Редагувати стіл» → натискання на «Швидкий доступ» → панель «Вигляд» → «Великі значки» (або «Розмір значка: 56 пікселів») → видно одразу → «Збережено».
2. **Один значок більший, інші менші:** у режимі редагування натискання на «Пошта» → «Розмір значка» 72 → «Ширина: 2 клітинки» → інші не змінюються.
3. **Блок у блоці:** виділити «Пошта», «Календар», «Завдання» (Shift+натискання) → «Згрупувати» → «Колонка» → новий внутрішній блок, ширина «30 %»; решта лишається сіткою.
4. **Перетягнути значок з блоку на стіл / в інший блок:** потягнути «GitHub» (телефон: довге натискання) за межі блоку → підсвічується стіл → відпустити → став окремим ярликом того ж вигляду. Без миші: «Перемістити в…» → «Робочий стіл».
5. **Значок у меню або на сторінку:** потягнути «Нотатки» на бічне меню → підсвічене місце → відпустити → пункт меню з малим значком. Або «Перемістити в…» → «Меню» / «Сторінка Пошта, верхня панель». «Скасувати» (Ctrl+Z) повертає назад.

## 6. Ризики
- Повернення стану до старого випуску може перезаписати `blok` → колонка резервної копії + кнопка відновлення (A).
- Продуктивність на глибоких деревах на телефоні → ліміти (глибина 4, 400 вузлів), мемоізація обчислень на блок (B).
- Перетягування через межі меню/сторінки/полотна — найскладніша частина; меню вже має власний контролер перетягування → адаптер, без другої паралельної системи (D).
- Права: елемент із технічного простору не може потрапити до особистого меню → `niet-toegestaan-in-ruimte`, сервер перевіряє повторно.
- Кольори/контраст: довільний колір може стати нечитабельним → панель попереджає при контрасті < 4,5:1.

## 7. Рішення для Павла (макс. 3)
1. **Куди можна переносити елемент поза робочим столом?** Рекомендовано: спершу полотно + блоки + бічне меню; секції сторінок — другим кроком.
2. **Окремо для кожного пристрою чи всюди однаково?** Рекомендовано: розкладка окрема для кожного пристрою (як у v3 зараз), колір/значок спільні для всіх пристроїв.
3. **Дозволяти накладання у вільному режимі («вільно»)?** Рекомендовано: ні, елементи розсуваються вбік (як на полотні зараз), з перемикачем «Дозволити накладання» для тих, хто хоче.
