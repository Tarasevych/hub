# SSO-навігація екосистеми v1

## Мета
Усі виробничі (production) піддомени поводяться як розділи єдиної екосистеми, а не як непов'язані між собою сайти.

## Модель сесій
- Hub зберігає свою наявну сесію Hub, ізольовану в межах вкладки (`tab-scoped`).
- Кожен сервіс підтримує власну `host-only` `HttpOnly` сесію, яка обирається за несекретним ідентифікатором вкладки (`tab ID`).
- Двохвилинний одноразовий код передачі (`handoff`) переносить обраний обліковий запис між сервісами в межах тієї самої вкладки браузера.
- Навігація «сервіс — сервіс» та «сервіс — Hub» ніколи не передає в URL-адресах access-токени, ідентифікатори облікових записів або адреси електронної пошти.

## Потоки навігації
- Hub -> сервіс: сесія Hub створює handoff для цільового сервісу.
- Сервіс -> сервіс: поточна сесія сервісу створює handoff через Hub.
- Сервіс -> Hub: поточна сесія сервісу створює handoff для Hub; Hub споживає його у свою сесію вкладки.
- Прямий візит до сервісу без входу: сервіс перенаправляє користувача до Hub із параметром `continue=<service>`; після входу через Google Hub повертає користувача назад через handoff.

## Джерело істини
Бекенд Hub залишається єдиним джерелом істини щодо користувачів, статусів, робочих просторів, сповіщень, дозволів та аудиту.

## Контракт інтерфейсу (UI contract)
Усі сервіси використовують однаковий порядок глобальної бічної панелі (rail), токени теми, перемикач мови, індикатор поточного сервісу, контекст профілю та лічильник сповіщень.
