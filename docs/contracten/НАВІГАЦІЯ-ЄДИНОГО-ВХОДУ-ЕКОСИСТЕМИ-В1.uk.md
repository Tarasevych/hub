# SSO-навігація екосистеми v1

## Мета
Усі виробничі (робоче середовище) піддомени поводяться як розділи єдиної екосистеми, а не як непов'язані між собою сайти.

## Модель сеансів
- Hub зберігає свою наявну сеанс Hub, ізольовану в межах вкладки (`tab-scoped`).
- Кожен сервіс підтримує власну `host-only` `HttpOnly` сеанс, яка обирається за несекретним ідентифікатором вкладки (`tab ID`).
- Двохвилинний одноразовий код передачі (`handoff`) переносить обраний обліковий запис між сервісами в межах тієї самої вкладки оглядача.
- Навігація «сервіс — сервіс» та «сервіс — Hub» ніколи не передає в URL-адресах access-маркери доступу, ідентифікатори облікових записів або адреси електронної пошти.

## Потоки навігації
- Hub -> сервіс: сеанс Hub створює передача контексту для цільового сервісу.
- Сервіс -> сервіс: поточна сеанс сервісу створює передача контексту через Hub.
- Сервіс -> Hub: поточна сеанс сервісу створює передача контексту для Hub; Hub споживає його у свою сеанс вкладки.
- Прямий візит до сервісу без входу: сервіс перенаправляє користувача до Hub із параметром `continue=<service>`; після входу через Google Hub повертає користувача назад через передача контексту.

## Джерело істини
Серверна частина Hub залишається єдиним джерелом істини щодо користувачів, статусів, робочих просторів, сповіщень, дозволів та аудиту.

## Контракт інтерфейсу (UI contract)
Усі сервіси використовують однаковий порядок глобальної бічної панелі (rail), маркери доступу теми, перемикач мови, індикатор поточного сервісу, контекст профілю та лічильник сповіщень.
