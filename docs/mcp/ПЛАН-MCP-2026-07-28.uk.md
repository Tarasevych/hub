## 2. Принципи

1. **Подвійна ера.** До кінця 2027 року більшість клієнтів (claude.ai, ChatGPT, Gemini) говорять «старою» мовою з `initialize`. Сервер відповідає **обом**:
   `initialize` → 2025-11-25; запит із `_meta.io.modelcontextprotocol/protocolVersion = 2026-07-28` → сучасна гілка. Нічого не вимикаємо, доки є живі клієнти.
2. **Одна логіка для обох ер.** Правила доступу (`v2Roep`: простір, рядок прав, політика ШІ, підтвердження людини) — одні; ери відрізняються лише обгорткою.
3. **Небезпечне типово «Вимкнено», але можна обрати «Завжди».** Нові можливості з ризиком (MCP Apps, задачі розгортання, URL-elicitation сторонніх OAuth)
   мають перемикач на `/agenten` з позначкою «!» і поясненням наслідків.
4. **Кожна дія — у центрі сповіщень.** Нові типи подій (elicitation, задача, підписка, Origin-відмова) з іконкою служби, фільтром і розгорнутим описом.
5. **Тексти UI та інструментів — лише українською/нідерландською** (`p(uk, nl)` + `vertaalSchema`); англійська — лише технічні терміни.
6. **Кожен випуск окремо встановлюваний і відкочуваний:** резервна копія на R:\ → тест патча → перевірка накладання (overlay) → `orch pakket` →
   GitHub Release asset (TRACE-001) → встановлювач `na_bevestiging`.

## 3. Проміжні випуски

Позначення: **MUST/SHOULD** — рівень вимоги у специфікації. «Сайт» — що бачить людина. «Перевірка» — що має бути фактично перевірено до видачі.

### R0 · Виправлення схем браузерних інструментів — ✅ готово (фіксація `296b04f`, PR Tarasevych/hub#73)
- `backend/connector-v2-browser.ts`: псевдоніми chrome-devtools-mcp проходять `vertaalHulpmiddel`/`vertaalSchema`; примітка — uk/nl.
- `backend/connector-v2.ts`: запобіжник у `tools/list` — кожна схема перекладається, жоден `description` не лишається об'єктом.
- Тест `tests/eenheid/devtools-schema-tekst-20261112.test.ts`: без виправлення 80 помилок, з ним 0.
- **Ефект:** `click`, `fill`, `fill_form`, `hover`, `take_snapshot`, `take_screenshot`, `list_pages`, `new_page`, `navigate_page`, `select_page`,
  `close_page`, `press_key`, `wait_for`, `list_console_messages`, `list_network_requests` знову видимі в Claude.
- **Перевірка після встановлення:** перепідключити конектор у claude.ai → у списку немає «excluded … description must be string».

### R1 · Безпека транспорту й OAuth за 2025-11-25 (без зміни ери)
- **Origin (MUST):** на `/claude`, `/<agent>`, `/mcp`: якщо заголовок `Origin` присутній і не в списку дозволених — `403`. Сервер-сервер без `Origin` — як зараз.
- **RFC 8707 (MUST):** `resource` обов'язковий у `/authorize` і `/token`; перевірка аудиторії токена для кожного агента окремо (вже є для v2 — вирівняти старий `/mcp`).
- **RFC 9207:** `iss` у відповіді авторизації + `authorization_response_iss_parameter_supported: true` у метаданих.
- **CIMD (SHOULD):** `client_id_metadata_document_supported: true`; `client_id` = HTTPS-URL → завантаження документа із захистом від SSRF
  (лише HTTPS, блок приватних/loopback/link-local IP, перевірка після переадресацій, ліміт розміру й часу), точний збіг `client_id` і `redirect_uris`.
  DCR лишається (застарілий, але claude.ai ще ним користується).
- **Step-up (SHOULD):** відмова через брак права → `403` + `WWW-Authenticate: Bearer error="insufficient_scope", scope="…"` замість текстової помилки.
- **Помилки валідації вхідних даних** → результат інструменту з `isError: true` (SEP-1303), а не помилка протоколу.
- **Пакети JSON-RPC** у `/mcp` — лише для версії 2025-03-26; для новіших — `-32600`.
- **Детермінований порядок** `tools/list` (сортування за групою, потім за назвою).
- **Сайт:** у центрі сповіщень — нові події «Відмова Origin», «Реєстрація клієнта через CIMD», «Запит додаткових прав»; на `/agenten` — рядок «Як підключено» (DCR/CIMD).
- **Перевірка:** юніт-тести на кожен пункт (403 Origin, `invalid_target`, `iss`, SSRF-блок для 127.0.0.1/10.0.0.0/8/169.254.0.0/16/[::1], step-up);
  інспектор: `mcp-inspector --cli https://mcp.tarasevych.com/claude --transport http --stored-auth-only --method tools/list --strict`.

### R2 · Якісні інструменти: структуровані результати, іконки, анотації
- `outputSchema` + `structuredContent` для інструментів читання (пошта, файли, дошка, календар, GitHub, стан розгортання); текстова копія JSON у `content` (SHOULD).
- `icons` для кожної групи (пошта, Drive, GitHub, браузер, сервер …) — ті самі, що в меню сайту; `title` — uk/nl.
- Повні анотації: `idempotentHint`, `openWorldHint` (пошта/GitHub/браузер — `true`), `destructiveHint` для видалення.
- Діалект JSON Schema 2020-12 явно (`$schema`), без `number` у параметрах, які пізніше стануть `x-mcp-header`.
- **Сайт:** на сторінці агента — картка інструменту з іконкою, анотаціями («лише читання», «змінює дані», «незворотно») і прикладом результату.
- **Перевірка:** тест «кожен `structuredContent` проходить свій `outputSchema`» (ajv) для всіх інструментів; `--strict` інспектора без зауважень.

### R3 · Ресурси, шаблони ресурсів, промпти, автодоповнення
- **Ресурси:** `mr://mail/{account}/{messageId}`, `mr://drive/{fileId}`, `mr://bord/{item}`, `mr://agenda/{event}`, `mr://uitrol/{versie}` — лише в межах прав агента
  і приватного/технічного простору; «не знайдено» → `-32602` (2026-07-28).
- **Промпти** (uk/nl): «Огляд пошти за день», «Підготовка до зустрічі», «Діагностика сервісу», «Звіт про випуск», «Розбір issue GitHub».
- **`completion/complete`** для аргументів (рахунки пошти, репозиторії, назви застосунків, вкладки).
- **Сайт:** на `/agenten` — окремі перемикачі «Ресурси» і «Промпти» для кожного агента (типово увімкнено лише читання); журнал читань у центрі сповіщень.
- **Перевірка:** `resources/list`, `resources/templates/list`, `resources/read`, `prompts/get` через інспектор; ізоляція просторів (ресурс іншого користувача → `-32602`, запис в аудит).

### R4 · Сучасна ера 2026-07-28 (подвійна підтримка) — головний випуск
- **`server/discover` (MUST):** `supportedVersions`, `capabilities` (+ `extensions`), `instructions`, `ttlMs`.
- **Без стану (SEP-2575/2567):** кожен запит несе `_meta` з версією та можливостями клієнта; сервер не покладається на попередні запити;
  `Mcp-Session-Id` ігнорується; для сучасних клієнтів GET/DELETE → `405`.
- **Заголовки:** перевірка `MCP-Protocol-Version` == `_meta` (інакше `400`/`-32020`), `Mcp-Method`, `Mcp-Name` для `tools/call`/`resources/read`/`prompts/get`
  (Base64-sentinel для не-ASCII); невідомий метод → `404`/`-32601`; непідтримувана версія → `-32022` з `data.supported`; відсутня можливість клієнта → `-32021`.
- **`resultType: "complete"`** у кожному результаті; `ttlMs` + `cacheScope: "private"` у списках і `resources/read` (SEP-2549).
- **`subscriptions/listen`** замість GET-потоку: перше повідомлення `notifications/subscriptions/acknowledged`, позначка `subscriptionId`;
  події `tools/list_changed` (увімкнення технічного профілю, зміна прав на сайті).
- **Журналювання й трасування:** рівень журналу з `_meta.io.modelcontextprotocol/logLevel`; `traceparent`/`tracestate` → журнал сервера (SEP-414).
- **Скасування:** закритий потік відповіді = скасування; робота зупиняється, дальші повідомлення не надсилаються.
- **Стара ера не змінюється:** `initialize` → 2025-11-25, GET-потік і `ping` працюють як раніше.
- **Сайт:** на сторінці агента — «Ера протоколу: стара / сучасна» за останнім запитом, версія, клієнт; у центрі сповіщень — помилки узгодження версії з поясненням.
- **Перевірка:** інспектор у трьох режимах — `--protocol-era legacy`, `modern`, `auto` — для `tools/list`, `tools/call`, `resources/read`;
  тести на `-32020/-32021/-32022`, `405`, `resultType`, `ttlMs`; claude.ai після встановлення працює без перепідключення.

### R5 · Підтвердження людиною через MRTR / elicitation (замість «pending»)
- Інструменти, що зараз повертають `pending`, у сучасній ері повертають `resultType: "input_required"` з `inputRequests`:
  - **форма** — для простого «Так/Ні» з поясненням наслідків (надіслати лист, видалити файл, розгорнути застосунок);
  - **URL-режим (MUST для секретів і сторонніх OAuth)** — посилання на сайт `mcp.tarasevych.com/bevestig/<id>` з passkey; без персональних даних в URL.
- `requestState` — підписаний HMAC, прив'язаний до `userId` з токена, з терміном дії й захистом від повторного використання (MUST: вважати ворожим).
- Запит лише тих типів введення, які клієнт оголосив; інакше — нинішній шлях через сайт (стара ера теж лишається на ньому).
- **Сайт:** спільна черга «Очікує вашого рішення» для обох шляхів; тост + сповіщення з іконкою служби; «Завжди дозволяти для цього інструменту» — з «!» і поясненням ризику.
- **Перевірка:** підробка/повтор `requestState` → відмова й запис в аудит; таймаут; скасування; той самий лист не надсилається двічі (ідемпотентність).

### R6 · Довгі операції: розширення Tasks (`io.modelcontextprotocol/tasks`, Beta)
- Задачами стають: розгортання й відкат застосунків, `uitrol`, резервні копії, Docker-операції, глибока діагностика, синхронізація репозиторію.
- `tasks/get` для опитування, `tasks/update` для введення посеред роботи; прогрес (`notifications/progress`) у сучасному потоці.
- Ручки задач випадкові, з терміном дії, прив'язані до `<userId>:<handle>` (MUST перевіряти кожен запит).
- **Сайт:** панель «Задачі агентів» — стан, прогрес, кнопка «Скасувати», посилання на журнал; кожна зміна стану — у центрі сповіщень.
- **Перевірка:** розгортання тестового застосунку як задача від початку до кінця; переривання з'єднання не зупиняє задачу; скасування зупиняє.

### R7 · MCP Apps (`io.modelcontextprotocol/ui`, Stable) — інтерактивні панелі в чаті
- `ui://`-ресурси (`text/html;profile=mcp-app`): дошка задач, стан розгортання, попередній перегляд листа, огляд сервісів хабу.
- Жорсткий CSP, без зовнішніх скриптів, лише дії через ті самі інструменти з тими самими правами.
- **Сайт:** перемикач «Інтерактивні панелі» для кожного агента — типово **Вимкнено**, можна «Завжди», з «!» і поясненням (виконання HTML у клієнті).
- **Перевірка:** `mcp-inspector --cli … --method tools/list --app-info --advertise-apps`; панель відкривається в Claude; дія з панелі проходить ту саму перевірку прав.

### R8 · Клієнт `mcp-klant` і вбудований інспектор на сайті
- `MCP_KLANT_VERSIES`: додати 2025-11-25 і 2026-07-28 (`server/discover` → сучасна, інакше `initialize`); CIMD як спосіб входу до сторонніх серверів;
  перевірка `iss`; заборона передачі токенів (MUST NOT); SSRF-захист при отриманні метаданих.
- Сторінка `/agenten` → «Інспектор»: список інструментів/ресурсів/промптів будь-якого підключеного сервера (свого чи стороннього), пробний виклик
  (лише читання — одразу; запис — через підтвердження), показ сирого JSON-RPC, ери й помилок.
- **CI:** GitHub Actions — інспектор `--strict` у двох ерах проти тестового стенду (без production-токенів).
- **Перевірка:** підключення до еталонного сервера з `modelcontextprotocol/servers` у трьох ерах; власний сервер через власний клієнт.

### R9 · Виявлення та реєстр
- **Server Card** (`ext-server-card`, Beta): HTTP-опис сервера до підключення (назва, іконка, ери, способи авторизації).
- **`server.json`** (`name: com.tarasevych/mijn-ruimte`, `remotes[]` для кожного агента).
- **Публікація в реєстрі MCP** — лише після рішення власника (сервер приватний; реєстр приймає лише публічно досяжні; доступ за OAuth лишається).
  Підтвердження домену через `https://tarasevych.com/.well-known/mcp-registry-auth` або DNS TXT — ключем власника, агентам не передається.
- **Skills over MCP** (`ext-skills`, Beta): навички (порядок випуску, AGENTS.md-правила) як ресурси.
- **Перевірка:** `curl https://registry.modelcontextprotocol.io/v0.1/servers?search=tarasevych` після публікації; Server Card валідна за схемою.

## 4. Порядок і залежності

```
R0 ──► R1 ──► R2 ──► R3 ──► R4 ──┬─► R5
                                  ├─► R6
                                  └─► R7
R1 ──────────────────────────────────► R8 (клієнт можна паралельно після R1)
R4 ──────────────────────────────────► R9
```

R0–R3 не змінюють ери й безпечні для всіх поточних клієнтів. R4 — найбільший ризик: встановлювати окремо, з повним прогоном інспектора в обох ерах
і з перевіркою, що claude.ai/ChatGPT/Gemini працюють без перепідключення. R5–R7 потребують R4 (MRTR і розширення живуть у сучасній ері),
але для старої ери кожен з них має запасний шлях (сайт).

## 5. Процедура кожного випуску

1. Гілка `feature/mcp-001-rN-YYYYMMDD-HHMMSS`, `orch taak-start`, `versheid --fase start`.
2. Реалізація + юніт-тести (`node scripts/eenheidstests.mjs <фільтр>`), `npm run typecheck:server`, інспектор `--strict`.
3. `versheid --fase overdracht`, `ORCH-OVERDRACHT.json`, `ontwikkelarchieven/MCP-001.json` (TRACE-001).
4. `orch pakket` → `mijn-ruimte-<версія>.tar.gz` + GitHub Release asset з тією самою SHA-256.
5. Встановлення (власник, режим `na_bevestiging`): **резервна копія на R:\ → тест патча → перевірка накладання (overlay)** → `mijn-ruimte-installeer`.
6. Після встановлення: `/api/version`, інспектор проти production лише на читання (`--stored-auth-only`), перепідключення claude.ai, запис у `geinstalleerd.json` (лише встановлювач).
7. Відкат: попередній пакет через той самий встановлювач; кожен випуск зворотно сумісний з попереднім за даними БД (міграції лише додають).

## 6. Свідомо не входить

- Вимкнення старої ери, DCR, HTTP+SSE — специфікація дозволяє видалення не раніше 2027-07-28; рішення окремо.
- Sampling і Roots у сервері — застарілі (SEP-2577), не впроваджуємо.
- OAuth Client Credentials та Enterprise-Managed Authorization — немає сценарію для приватного хабу; повернемося на запит.
- Публікація в реєстрі без явного рішення власника.
