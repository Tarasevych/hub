# Зона 9. Технічна архітектура й етапи / Architectuur

Задача HUIS-001 · етап 0 · 10.11.2026 · статус: на погодженні власника

Зона — єдине джерело чисел реального часу, строків, зберігання, паспорта демо-дому, реєстру сценаріїв і порядку етапів; вона ж веде розділ «Система / Systeem». Джерела: план HUIS-001 (§1, §3, §3.8, §4) і [дизайн-мова «Живий дім»](../ДИЗАЙН-МОВА-ЖИВИЙ-ДІМ-20261110.uk.md) (далі — ДМ). Граматика адрес — із зони [«Каркас»](01-КАРКАС.uk.md): аркуш `?blad=<вид>:<id>`, діалог `?dialoog=`, момент `?t=`. Шкала етапів — 0–12 (§16).

## 0. Що змінилося проти попередньої версії

- **«Живий дім»** замість «Теплої точності»: заборони скла, неба й градієнтів знято. Сторінки Системи стоять на тихому небі, усе з числами — на папері `--panel`, скло `--hv-glas` — лише шапка, навігація, оболонка аркушів і «Команда / Opdracht».
- **Дозволи** (план §3.8): матриця `shared/huis-gevaar.ts` задає лише рівень дії й ритуал людини. Прибрано стелі, «найвищий дозвіл», вимкнене «Завжди» для критичного, «режим ніколи не знімає охорону», «критичне на панелі — лише перегляд», строк «Завжди» 30 днів.
- **Порядок етапів** — план §4; посилання переведено, наслідки — §16. **Усі інструменти керування** — у шкалі: аркуші всіх класів — етап 2, інструменти агентів — етап 5; повноту перевіряє збірка (§4).
- **Звірено з ДМ:** `/paneel/<profiel>/<id>`; стани «очікує → виконується → не виконано»; час ходу за класом; перемикачі Системи мають «i», а не «!»; `?dialoog=stoppen`, `?dialoog=start`; прапорець `huis-levend`; назви інструментів — із зони [«Помічник і агенти»](08-ПОМІЧНИК-І-АГЕНТИ.uk.md).

## 1. Вигляд зони

Розділ «Система» відкривається картою `hv-systeemkaart`: заголовки груп — на тихому небі (`--text`, 20/700), групи — паперові `hv-blok`, що згортаються. Симулятор, «Світ», діагностика й таблиці строків — паперові блоки. Небо в симуляції йде за часом дому з підписом «небо за часом дому / hemel volgt huistijd»; тривога (`.is-nood`) вимикає небо й скло. Знаки автора — алфавіт `hv-maker`: симулятор — `FlaskConical`, система — `Cpu`, оптимізатор — `Gauge`.

## 2. Контракт адаптера (`shared/huis-adapter.ts`)

```ts
interface HuisAdapter {
  manifest: { id; naam; herkomst: 'echt'|'simulatie'; pad; configSchema;
              wachtMs;                              // перша відповідь, ≤ 10 000
              looptijdMs: Record<Klasse, number> }; // хід класу
  start(ctx: { woningId; klok; geheim(); meld(g) }); stop();
  ontdek(); koppel(stap, invoer);   // кроки сполучення: «фізична дія, N с»
  stuur({ opdrachtId; bronId; mogelijkheid; waarde; deadline }): { aanvaard; fout? };
  gezondheid(): { stand: 'goed'|'verzwakt'|'auth_vereist'|'limiet'|'offline'; detail } }
// meld: toestand | voorval | beschikbaarheid | ontdekt | verdwenen
```
Адаптер не пише в базу й не знає людей. Єдиний приймач `backend/huis/inname.ts` веде тінь «бажане / спостережене», історію й шину з автором. `stuur` лише приймає; підтвердження — подія `toestand`. Адаптер Home Assistant загортається в контракт без зміни поведінки.

## 3. Симулятор і демо-дім

- **Походження — властивість оселі** (`huis_woningen.herkomst`). Перший запуск (`/overzicht?dialoog=start`) створює «Демо-дім / Demowoning»; справжній дім починається порожнім. Сервер не під'єднує адаптер `echt` до демо-оселі й навпаки: змішаного дому немає, тож симуляцію позначають чип `hv-sim`, штамп, кут графіка, сповіщення й Журнал, а не колба на елементі. Фраза «жоден справжній пристрій не змінено» завжди правдива.
- **Зовнішні канали** демо-оселі сервер блокує, доки власник не ввімкне «Зовнішні сповіщення / Externe meldingen» (з «i»).
- **Вихід:** майстер «Перенести налаштування / Instellingen overnemen» (`hv-vervang`): кімнати, план, сцени й автоматизації переносяться чернетками «Спостереження / Meekijken»; дозволи, коди й історія — ні: у справжньому домі кожен дозвіл починається з «Вимкнено».
- **Ядро** — чисті функції `shared/huis-sim/`: `f(зерно, час дому, журнал команд і ручних значень)`; минулу добу перераховує зерно, тож стрічка доби працює на етапі 1 без історії. Еталон тестів — хеш добової траси.
- **Світ / Wereld:** ручне значення (датчик, людина, місце авто, вітер, ціна години) — подія автора «симулятор» з позначкою «ручне / handmatig» до «Повернути до сценарію / Terug naar scenario». «Додати віртуальний пристрій / Virtueel apparaat toevoegen» — будь-який тип із зони [«Пристрої»](03-ПРИСТРОЇ.uk.md), тож аркуш кожного класу можна випробувати. **Траси / Sporen:** записати, відтворити, зберегти як сценарій. **Збої** — звичайні перемикачі, не `hv-stand`.

**Два годинники** (у справжньому домі збігаються). Справжній час — «Повернути / Ongedaan maken» 10 с, очікування й хід класу, заставка 2 хв і повернення на «Дім» 5 хв, замикання `deur` 30 с, пауза коду 5 хв, сеанси й будь-який строк, який задав власник (за ×600 строк у 30 днів сплив би за 72 хвилини). Час дому — розклади, тарифи, графіки, тихі години, підсумок дня, рамки «години» й «бюджет дій», ескалація, поїздки й польоти. Від ×10 зовнішні канали мовчать; новий `hv-verzoek` ставить ×1 з поясненням у `hv-sim`; ×600 стає на паузу після 30 діб дому.

**Паспорт** (`paspoort.ts`): «Демо-дім · Wilgenlaan 12», Утрехт; еталонний момент — понеділок 9 листопада 2026, 14:30. 14 кімнат, сад, шопа; близько 120 пристроїв — екземпляр кожного типу, по одному «недоступний», «стан припущено», «застаріло», «не виконано»; P1 на три фази, сонце 4,2 кВт, батарея 10 кВт·год, тепловий насос, тариф на 48 год; четверо мешканців і гість. Гараж: електромобіль, авто, два електровелосипеди, самокат, мопед, два дрони з доком, пилосос, косарка. Камер 4, кадр — SVG із сервера раз на 2 с. Макет — 10 кімнат, 48 пристроїв, гараж повний. **Сценарії** (`scenarios.ts`) — 36: тло 3, енергія 8, безпека 7, гараж 11, агенти 3, система 4; макет бере 15.

## 4. Реєстр, матриця ризику, ворота

- **Реєстр.** `huis_apparaten` (0128) — таблиця сутностей, не перейменовується; над нею нова `huis_hardware`. Додаються `hardware_id`, `domein`, `klasse`, `naam_uk`, `naam_nl`, `aliassen`, `aangenomen`; до `huis_toestanden` — `gewenst`, `oorzaak`. Міграції від 0200, RLS лише через `app.huis_is_lid()`.
- **Повнота.** Реєстр аркушів `src/huis/bladen/`: клас → «Керування / Bediening · Історія / Geschiedenis · Налаштування / Instellingen». Тест падає, якщо клас не має аркуша, можливість — рядка матриці, дія — інструмента з'єднувача.
- **Матриця ризику** `shared/huis-gevaar.ts`: «можливість × напрям → рівень → ритуал людини»; замінює `KRITIEKE_SOORTEN` і живить знак із ритуалом, `hv-risico`, `hv-gevaar`, реєстр `/instellingen/risico`. Дозволів не обмежує. Рішення — в `orchestratie/BESLUITEN.md` з кодом етапу 2.
- **Дозволи** — `huis_beleid`: (дія × виконавець) → режим і необов'язкові рамки власника. Рядка немає — «Вимкнено».
- **Ворота** (інтерфейс, рушій, Команда, з'єднувач): джерело («лише читання / alleen-lezen») → роль («немає доступу / geen toegang») → людині — ритуал рівня; виконавцю — пауза → режим → рамки. Відмова називає ворота: «Не виконано: дію вимкнено для сцен / Niet uitgevoerd: actie staat uit voor scènes».
- **Сухий прогін** `POST /api/huis/gevolg`: зачеплене, «що станеться», «пов'язано з», «як повернути», чинний режим виконавця; його показують `hv-gevolg`, `hv-opdracht`, `hv-gevaar`, `hv-voorstel`. Збірка відхиляє орган без підказки.

## 5. Дозволи на сервері

- **Режими** (ДМ §10): «Вимкнено / Uit» — не виконується й агентові не оголошується; «Питати / Vragen» — `hv-verzoek` без нав'язаного строку; «Завжди / Altijd» — виконується в рамках власника зі знаком автора й `hv-toost`. Окремо для сцен, автоматизацій, оптимізатора й кожного агента; типово «Вимкнено»; власник може обрати будь-який режим для будь-якої дії.
- **Змінює лише власник** на особистому пристрої; «Завжди» для небезпечної чи критичної дії — з підтвердженням входу платформи (перевірка особи, не обмеження). На `/paneel/*` і `tv` — лише читання. Записує в `huis_beleid` тільки ця функція; перевірка — `rechten.sql`.
- **Агент** не має маршруту чи інструмента, що змінює дозволи, рамки, паузу, ролі чи секрети — ні свої, ні чужі.
- **Журнал обов'язковий:** кожна зміна (груповий орган — запис на кожну дію) і кожна дія за дозволом — «хто · що · чому · було → стало · через який дозвіл» у `huis_handelingen` і `emitCanonicalNotice`; лише додавання.
- **«!»** біля `hv-stand` небезпечної й критичної дії пояснює ризик; за «Завжди» стоїть постійна позначка, яку не закрити. **«! N»** сервер рахує в знімку: чинні «Завжди» небезпечних і критичних дій і найвищий рівень. **Пауза** (`huis_pauze`, `?dialoog=stoppen`) режимів не змінює; відновлює лише власник. **Строк власника** минає за справжнім часом — режим стає «Вимкнено», запис від автора «система».
- **Схвалення запиту** — дія людини з ритуалом рівня: критичне — рейка й підтвердження входу на місці.

## 6. Реальний час

- **Потік** `POST /api/huis/stroom` (`fetch`, `ReadableStream`; тіло — контекст сеансу й `laatsteId`) — окремий обробник перед маршрутизатором, бо той буферизує відповіді.
- **Кадри:** `momentopname` → `delta` → `opnieuw` → `rechten` → `afgemeld`; `spoed` (тривога, стан команди, запит, пауза) — одразу, решта — раз на 250 мс; сигнал життя 15 с; надолуження з кільця (2000 кадрів або 5 хв). Знімок несе фазу неба, «! N» і паузу. Запасне: три невдачі або 45 с тиші — опитування 30 с. Ліміти: 6 потоків на людину, 1 на екран, 24 екрани на оселю.
- **Стани команди** (ДМ §9): серверна машина (`verzonden → aangenomen → bevestigd | geweigerd | verlopen`) внутрішня; інтерфейс показує «очікує / wacht» до 10 с → для класів із ходом «виконується / bezig» до часу класу (штори 60 с, ворота й двері гаража 90 с, клапан 30 с, замок 15 с, решта 60 с) → спостережене або «не виконано / niet uitgevoerd»; без зворотного зв'язку — «стан припущено».
- **Застаріло після:** P1 60 с; замок, охорона 5 хв; мережеві пристрої 15 хв; батарейні датчики — два інтервали звіту; транспорт 2 хв у русі, 30 хв на стоянці; дрон у польоті 10 с.

## 7. Історія, Журнал, аудит

Шина — у пам'яті; події — `huis_gebeurtenissen` (чистка — у нічному обслуговуванні); аудит — `huis_handelingen`: для `mijnruimte_app` лише INSERT, хеш попереднього запису.

| Дані | Справжній дім | Демо-дім |
|---|---|---|
| сирі виміри | 14 днів | ≤ 200 тис.; від ×10 не пишуться |
| згортки 5 хв / година / доба | 90 днів / 10 років / безстроково | ≤ 500 тис. |
| історія станів, журнал подій | 400 днів | ≤ 200 тис.; ≤ 50 тис. |
| аудит дій і дозволів | 2 роки | ≤ 20 тис. |
| сліди запусків; маршрути | 30 днів | 20 останніх; ≤ 30 діб дому |

≈ 130 тис. рядків на добу, < 1,5 ГБ. Розділів таблиць немає: BRIN і нічне видалення пакетами.

## 8. Рушій без сеансу людини

- `backend/huis/motor.ts` у процесі сервера; ядро (етап 2) — планувальник, `huis_timers`, ворота, сліди `huis_runs`, карантин петель; редактор і версії — етап 5.
- Автоматизація діє від імені людини, що її ввімкнула (`alsGebruiker`, RLS не обходиться); втратила людина доступ — правило на паузі. Кожен крок проходить `hv-stand` виконавця й рамки.
- Режим дому — сцена: крок «зняти охорону» в ньому виконується за дозволом сцен (типово «Вимкнено»), як і будь-який інший.
- Оптимізатор — окремий виконавець; до етапу 7 — тіньовий режим («зробив би»).
- **Підтвердження входу** зараз діє 300 с на сеанс (`STAP_OP_MS`). Пропоную одноразове, прив'язане до хешу дії; до рішення тексти кажуть «Підтвердження діє 5 хв для цього сеансу / Bevestiging geldt 5 min voor deze sessie».

## 9. Екрани, сполучення, локальний шлях

- `huis_schermen`: профіль, кімната, розташування, щільність, тема, `indeling` (JSON із версією), кіоск. Адреса — `/paneel/<profiel>/<id>`; картинка й дані для прошивок — `/api/huis/scherm/<id>/beeld` і `/gezicht` (каркас §6).
- **Сполучення:** код із 6 цифр і QR створює сеанс «екран» без людини; власник підтверджує в `?dialoog=koppelen` входом платформи. Сеанс не підтверджує вхід і не змінює дозволів; діє до «Відкликати / Intrekken» або строку власника.
- **Дії людини на панелі** (ДМ §10, каркас §6): звичайна — одразу; чутлива — одразу, з «Повернути» 10 с, без коду; небезпечна — рейка; критична — особистий код як підтвердження входу й рейка, на `tv`, `horloge`, `strook`, `inkt` — «Підтвердьте на телефоні / Bevestig op je telefoon». Тому особисті коди — етап 6.
- **Локальний шлях:** у домашній мережі `huis.tarasevych.com` веде на ВМ (локальний DNS, сертифікат через перевірку DNS). Аркуш «Зв'язок» (`?blad=verbinding`, `hv-verbindingsketen`) показує «локально / lokaal» чи «через тунель / via tunnel»; `hv-versheid` лишається з трьома станами ДМ. Без локального шляху кнопки «Спробувати локально» немає, а в «Безпеці» стоїть «Без інтернету панелі не покажуть тривогу / Zonder internet tonen panelen geen alarm».

## 10. З'єднувач, сповіщення, пошук

- **З'єднувач:** `'huis'` у `Subdomein` і групу в `shared/connector-v2/catalogus.ts`; назва `<essentie>_<agent>_huis_tarasevych_com_gebruiker`. Повний набір — зона «Помічник і агенти» §7 і [«Гараж»](06-ГАРАЖ.uk.md) §10: читання, усі класи пристроїв, групи, сцени, правила, енергія, безпека, камери, транспорт, безпілотники, роботи, техніка, симулятор. Інструментів для дозволів, рамок, паузи, ролей, секретів і аудиту немає.
- **Два вимикачі — обидва власника:** група `huis` на сторінці з'єднувача і `hv-stand` агента для кожної дії. «Вимкнено» — дію не оголошено, виклик дає «не виконано» з назвою воріт. Назви пристроїв — недовірені дані.
- **Сповіщення** (`emitCanonicalNotice`): `huis.alarm` — тривога; `.toegang`, `.integratie`, `.automatisering`, `.agent` — важливо; `.apparaat`, `.energie`, `.voertuig`, `.systeem`, `.simulatie` — до відома.
- **Пошук** `POST /api/huis/zoek` з урахуванням прав; погода, свята, мапа — серверні джерела з кешем, у демо-домі — симулятор.

Старі корені `/integraties`, `/simulator`, `/schermen`, `/showroom`, `/planner` перенаправляються. «Секрети» — назва, дата, де вжито, без значень. Камера, мікрофон і місце — три перемикачі «Приватності», типово «Вимкнено», з «i».

## 12. Реєстр сутностей

Сутність — таблиці `huis_…` — етап: оселя, пристрій, сутність — woningen+, hardware, apparaten+ — 1 · журнал, аудит, симулятор, траси — gebeurtenissen, handelingen, sim_stand, sim_sporen — 1–2 · сцени, режими, групи, таймери, сліди; дозволи, рамки, пауза — scenes+, groepen, timers, runs; beleid, kaders, pauze — 2 · обране — voorkeuren — 1–3 · транспорт, поїздки, зони, місії, польоти — voertuigen, ritten, zones, missies, vluchten — 4 · автоматизації, версії, допоміжні величини, погодження — automatiseringen+, versies, hulpwaarden, voorstellen+ — 5 · екрани, особисті коди, версії плану — schermen, codes, plan_versies — 6 · тарифи, договори, плани оптимізатора — tarieven, contracten, plannen — 7 · люди, запрошення, згоди, правила сповіщень — leden+, uitnodigingen, toestemmingen, meldregels — 8 · гостьові коди, інциденти, камери — codes, incidenten, camera_beleid — 9 · тижневі розклади — weekschemas — 10 · виявлене, обслуговування — ontdekt, onderhoud — 11 · токени API — api_tokens — 12.

Кожна міграція має перевірку в `rechten.sql` і тест «двічі поспіль» під `mijnruimte_app`. Прапорці: `huis-levend`, `huis-simulator`, `huis-stroom`, `huis-motor`, `huis-mcp`. Сервер: `backend/huis/{register,inname,bus,stroom,beleid,gevolg,zoek,historie,motor,schermen,mcp}.ts`.

## 14. Підказки, відмови, стани

- **Останній крок майстра.** «Що станеться: пристрій з'явиться в кімнаті „Кухня“ і в зведенні енергії. Пов'язано з: дозволи всіх виконавців — „Вимкнено“, змінює їх лише власник. Як повернути: сторінка пристрою → „Вилучити“.» / «Wat er gebeurt: het apparaat verschijnt in ‘Keuken’ en in het energieoverzicht. Hangt samen met: de toestemmingen staan voor alle uitvoerders op ‘Uit’, alleen de eigenaar wijzigt ze. Terugdraaien: apparaatpagina → ‘Verwijderen’.»
- **«i» біля «Зовнішні сповіщення».** «Що станеться: сповіщення симуляції підуть на телефон і в пошту з позначкою „Симуляція“. Пов'язано з: від ×10 вони знову мовчать. Як повернути: цей самий перемикач.» / «Wat er gebeurt: meldingen uit de simulatie gaan naar je telefoon en mail met het label ‘Simulatie’. Hangt samen met: vanaf ×10 zwijgen ze weer. Terugdraaien: dezelfde schakelaar.»
- **Відмова воріт.** «Чому ні: „Відкрити ворота“ для автоматизацій вимкнено. Що перевірити: режим у „Дозволах і небезпечних діях“. Що можна натомість: відкрити самому або обрати інший режим (лише власник).» / «Waarom niet: ‘Poort openen’ staat uit voor automatiseringen. Wat te controleren: de stand onder ‘Toestemmingen en gevaarlijke acties’. Wat wel kan: zelf openen of een andere stand kiezen (alleen de eigenaar).»
- **Не виконано за часом класу.** «Чому ні: ворота не відповіли за 90 с. Що перевірити: живлення приводу й зв'язок моста. Що можна натомість: спробувати ще раз або відкрити вручну.» / «Waarom niet: de poort reageerde niet binnen 90 s. Wat te controleren: de voeding van de aandrijving en de verbinding met de bridge. Wat wel kan: opnieuw proberen of handmatig openen.»
- **«Скинути симуляцію»** — небезпечна дія людини: `hv-gevaar` з рейкою й наслідком «демо-дім повернеться до 9 листопада, 14:30; Журнал лишиться».

**Стани:** адаптер «справний / in orde · послаблений / verzwakt · потрібен вхід / aanmelden nodig · ліміт / limiet · недоступний / niet bereikbaar»; симуляція «іде / loopt · пауза / pauze»; «ручне / handmatig»; іншим ролям — «лише перегляд / alleen bekijken»; порожні — `hv-leeg`.

## 17. Тести й ризики

- **Модульні** (роль `mijnruimte_app`): хеш траси; повнота «клас → аркуш → рядок матриці → інструмент»; рушій на ручному годиннику; два годинники; заборона `echt` у демо-оселі; аудит без UPDATE і DELETE; агент без маршруту до `huis_beleid`; типове «Вимкнено».
- **Наскрізні:** профілі ДМ §7, ТБ стрілками, `theme-inkt`, обидві теми й мови; `hv-stand` перемикає всі три режими для критичної дії; контраст точок неба; покриття підказок; етап 6 — тривога диму доходить до панелі без зовнішнього каналу.
- **Ризики:** тунель рве потік; без локального шляху панелі сліпі без інтернету; 5 хв підтвердження відкривають усі критичні дії сеансу; рушій ділить процес із сайтом; приймач обходить RLS; підміна через назви пристроїв.

## 20. Рішення для власника

1. Одноразове підтвердження входу, прив'язане до дії чи зміни дозволу, замість 5 хв на сеанс.
2. Зміни спільного коду платформи: обробник потоку в `server/start.ts`, сеанс «екран», служба моста на ВМ (етап 12).
3. Локальний шлях без тунелю для панелей.
4. Хто з мешканців бачить маршрути й місце; строки §7.
5. Камера, мікрофон і місце в браузері (`Permissions-Policy`).
6. Запасний канал справжніх тривог: дзвінок, SMS чи пошта.
7. Шлях живого відео й запис камер.
8. Власний файл шрифту Inter для візуальних тестів.
