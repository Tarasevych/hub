# Консолідація служби «Календар» (`agenda-v3` · Двосторонній CalDAV, `.ics` та безпечні переходи)

## 1. Призначення та архітектурні межі

Служба «Календар» (`hub.tarasevych.com/agenda`) об’єднує в одному вікні події Google Calendar, підписки `.ics` та зовнішні календарі протоколу `CalDAV` (`RFC 4791`: Apple iCloud, Fastmail, Nextcloud) із суворим розмежуванням особистого (`prive`) й технічного (`technisch`) просторів даних.

У межах консолідації реалізовано чотири ключові можливості за прапорцем `agenda-koppelingen-v1` (міграція `0315_agenda_koppelingen_vlag.sql`):

1. **Генератор стандартних файлів iCalendar (`RFC 5545`)** `bouwIcsGebeurtenis()` із побайтовим згортанням рядків UTF-8 до 75 октетів без розриву кириличних літер і повною взаємною сумісністю з розбирачем `ontleedIcs()`;
2. **Двосторонній запис подій у зовнішні календарі CalDAV** (`PUT` і `DELETE` із заголовками `If-None-Match: *` та `If-Match`, попередньою перевіркою привілеїв `current-user-privilege-set` та поверненням свіжої версії при конфлікті `412`);
3. **Одноклікове вивантаження будь-якої події у файл `.ics`** як самостійний спосіб перенесення або резервний шлях для календарів у режимі лише читання;
4. **Безвмістові швидкі переходи з картки події** до листів учасника в Пошті, картки контакту в «Контактах і відправниках» та пов’язаних нотаток зустрічі.

## 2. Безпека мережевих з’єднань, рядковий захист і нерозголошення адрес

- Усі зовнішні запити CalDAV (`PROPFIND`, `REPORT`, `GET`, `PUT`, `DELETE`) проходять виключно через захищений клієнт `pinnedFetch` (`backend/veilige-fetch.ts`): тільки `https:`, прив’язка розв’язаної IP-адреси проти підроблення серверних запитів, заборона автоматичних перенаправлень, обмеження часу очікування та розміру відповіді.
- Цільова адреса кожного ресурсу `.ics` перевіряється функцією `caldavAbsoluut()`, яка дозволяє лише той самий хост підключеного календаря (або офіційний секційний хост `pNN-caldav.icloud.com` для iCloud).
- Таблиці `app.agenda_koppeling`, `app.agenda_abonnement` та `app.agenda_externe_gebeurtenis` захищені `ENABLE ROW LEVEL SECURITY` та `FORCE ROW LEVEL SECURITY` із перевіркою власника й активного простору.
- Паролі застосунків CalDAV зберігаються виключно в зашифрованих конвертах `AES-256-GCM` із прив’язкою додаткових автентифікованих даних до власника, адреси та простору (`aad`).
- Під час швидких переходів учасника події до Пошти чи Контактів **жодна електронна адреса чи тема зустрічі ніколи не передається в адресному рядку оглядача**:
  - перехід до листів записує пошуковий стан на сервері й відкриває `/all?resume_context=1`;
  - перехід до картки контакту створює одноразовий короткочасний квиток `/contacts?contact_sprong=<uuid>`, який негайно вилучається з адресного рядка та одноразово обмінюється на сервері в межах того самого користувача й простору.

## 3. Серверні маршрути консолідованого Календаря

| Маршрут | Призначення | Захист і версійність |
|---|---|---|
| `POST /api/owner/agenda/caldav/schrijf-proef` | Перевірка прав запису колекції CalDAV через `PROPFIND Depth:0` | `ladePoort('agenda')` + `calendar.write` + прапорець |
| `POST /api/owner/agenda/caldav/bewaar-item` | Створення або зміна події CalDAV через `PUT` із `If-None-Match` / `If-Match` | Повторостійкий ключ + обробка конфлікту `412` |
| `POST /api/owner/agenda/caldav/wis-item` | Видалення події CalDAV через `DELETE` із перевіркою `If-Match` | Повторостійкий ключ + оновлення зовнішнього дзеркала |
| `POST /api/owner/agenda/afspraak/export-ics` | Побудова валідного файла `.ics` (`RFC 5545`) для обраної події | `ladePoort('agenda')` + безвмістовий запис аудиту |
| `POST /api/owner/agenda/deelnemer/sprong` | Підготовка безвмістового переходу до листів або контакту учасника | Перевірка власника та ізоляція простору |
| `POST /api/owner/agenda/deelnemer/sprong-lees` | Одноразовий обмін квитка `contact_sprong` на адресу учасника | Перевірка власника, простору й строку дії квитка |
| `POST /api/owner/agenda/notities/lijst` | Перелік нотаток зустрічі, прив’язаних до події в поточному просторі | `ladePoort('agenda')` + `FORCE RLS` |
| `POST /api/owner/agenda/notities/koppelen` | Прив’язка наявної або нової нотатки зустрічі з підтвердженням | `workspace.write` + `bevestigd: true` + повторостійкість |
| `POST /api/owner/agenda/notities/ontkoppelen` | Від’єднання нотатки від події календаря | `workspace.write` + `ladePoort('agenda')` |

## 4. Чесна поведінка при відмовах та сумісність при поверненні версії

Якщо зовнішній сервер CalDAV не надає прав запису (`403` або відсутність `write` у `current-user-privilege-set`), інтерфейс чесно повідомляє про режим лише читання та пропонує вивантажити подію у файл `.ics`. Якщо подію тим часом змінено на зовнішньому сервері (`412 Precondition Failed`), сервер не перезаписує чужу зміну, а завантажує свіжу версію події для свідомого вибору людини. У разі вимкнення прапорця `agenda-koppelingen-v1` зовнішні календарі CalDAV миттєво повертаються до режиму читання без втрати підключень чи синхронізованих подій.
