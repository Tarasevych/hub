# Повна інтеграція Хмари M4 — під'єднання та робота з кількома обліковими записами

Статус: **ЛИШЕ ДЛЯ РОЗРОБКИ / НЕ ДЛЯ ВСТАНОВЛЕННЯ**. База: 20261027-212158 + M1–M3. Жодного live сервера, OAuth-консолі, PostgreSQL, GitHub-проєкту чи адміністративного оновлення не змінено.

## 1. Зміст реалізації

- Серверне під'єднання Microsoft OneDrive Personal/Business, SharePoint, Dropbox, Box з OAuth 2.0 код уповноваження. Microsoft і Dropbox — PKCE S256; Box — конфіденційний код потік із серверним client секрет та випадковим одноразовим state. Microsoft `prompt=select_account` підтримує свідомий вибір наступного облікового запису. Dropbox/Box використовують власний інтерфейс постачальника.
- Відокремлені записи під'єднання за `(owner, ruimte, provider, external_subject)`. Один користувач може мати декілька облікових записів одного постачальника. Повторне під'єднання того самого віддалений суб'єкт оновлює його чинний запис, не створює дубль.
- Режим читання чи читання+запис. Backend маркер доступу-посередник обміну перевіряє наявність потрібних обсяги повноважень (Microsoft/Dropbox), status і додатковий локальний дозвіл; не довіряє бажаному типу операції з оглядача. Box встановлює OAuth обсяги повноважень у своїй developer-консолі, а тому «лише читання» у власному UI — локальне обмеження, **не обіцянка вузької сторонньої згоди**.
- Оглядач ніколи не отримує маркери оновлення та доступу. Маркери доступу й одноразові OAuth матеріали зберігаються AES-256-GCM у PostgreSQL, AAD містить власник+space+account запис id. База доступна лише системній серверній ролі.
- Перед початком OAuth визначаємо власник і `ruimte` у `ladePoort('cloud',...)`; після зворотний виклик звіряємо із записаним власником і простором, а стан споживаємо один раз. Зворотний виклик повертає лише код результату до `/overzicht`.
- Вимкнення відразу блокує локальний доступ, а потім пробує відкликати маркер доступу у Dropbox/Box. У Microsoft немає еквівалентного гарантованого окремого дозволу кінцева точка: локальний дозвіл блокується, а UI має пояснити, де відкликати сторонню згоду. Якщо віддалене відкликання не підтверджено — `disconnect_pending` (не «все відкликано»).
- Refresh-lock у PostgreSQL не дає двом оглядачам одночасно використати один Box маркер оновлення. При невизначеному результаті простроченого тимчасового права — `reauth_required`, а не небезпечний повтор.
- Збережено канонічний Google Suite B+ дозвіл; M4 не переназначає primary Gmail/Drive.
- React `CloudVerbindingCentrum` — окремий адаптивний компонент без дублювання CanonicalChrome. Він написаний, але **не вмонтований** у живу сторінку. Сигнал `BroadcastChannel` передає лише факт зміни, не обліковий запис/маркер доступу; між оглядачами/пристроями перелік оновлюється періодичним запитом до сервера. Обраний обліковий запис — `sessionStorage` поточної вкладки.

## 2. Зміни

- `backend/cloud-verbinding-m4.ts`: одноразові OAuth, перевірка коректності власника та простору, під'єднання, повторне під'єднання, перейменування, вимкнення.
- `backend/cloud-verbinding-m4-providers.ts`: постачальницькі OAuth URL, обмін маркерів доступу, `/me`, оновлення, відкликання.
- `backend/cloud-verbinding-m4-pg.ts`: потік/account сховище, AES-GCM, багатообліковий режим identity, PostgreSQL тимчасове право оновлення.
- `backend/cloud-verbinding-m4-token.ts`: посередник маркерів доступу за `accountId` та операцією, послідовне впорядкування оновлення.
- `backend/cloud-verbinding-m4-config.ts`: env-конфігурація, зафіксований зворотний виклик host і path.
- `backend/cloud-verbinding-m4-routes.ts`: передпускове середовище API `list/start/callback/rename/disconnect`.
- `backend/cloud-platform.ts`: нові маршрути всередині наявного `ladePoort('cloud')`.
- `backend/cloud-overdracht-credentials.ts`: новий посередник маркерів доступу тільки для не-Google постачальників і тільки за передпускове середовище пропускний бар'єр; Google залишається без змін.
- `migrations/0120_cloud_multi_account_connections.sql`: зашифровані дозволи, OAuth потоки, унікальність облікових записів, тимчасове право оновлення, RLS.
- `src/cloud/cloud-account-sync.ts`, `CloudVerbindingCentrum.tsx`, `cloud-verbinding-centrum.css`.
- `scripts/cloud-volledige-uitgave-poort.mjs`: 36 незалежних пунктів приймання, включно з кількома обліковими записами та багатооглядачевим доступом.

## 3. Необхідна конфігурація лише на ізольованому тестовому середовищі

Встановити окремі реєстрації застосунків / дозволені зворотний виклик URL в Microsoft Entra / Microsoft Account, Dropbox App Console, Box Developer Console:

- `CLOUD_MICROSOFT_CLIENT_ID`, `CLOUD_MICROSOFT_CLIENT_SECRET` (серверна конфіденційний застосунок, споживча та організаційна реєстрація згідно з підтримуваними типами облікових записів);
- `CLOUD_DROPBOX_CLIENT_ID`, `CLOUD_DROPBOX_CLIENT_SECRET`;
- `CLOUD_BOX_CLIENT_ID`, `CLOUD_BOX_CLIENT_SECRET`;
- `CLOUD_OAUTH_M4_REDIRECT_URI` — **точно** `https://api.tarasevych.com/api/owner/cloud/oauth/m4/callback` або `https://cloud.tarasevych.com/api/owner/cloud/oauth/m4/callback` за фактичним API reverse посередник;
- `CLOUD_OAUTH_TOKEN_ENCRYPTION_KEY_V1` — новий окремий 32-байтний серверний ключ, **не** вмикати його в архів; план ротації ключа ще потребує реалізації.

`CLOUD_M4_CONNECTIONS_STAGING=enabled` застосовувати тільки на **ізольованому тестовому стенді**, а не в робоче середовище. Типово API повертає `CLOUD_M4_NOT_RELEASED`. OAuth clients слід реєструвати для фактичного hostname, реального перенаправлення URI, точного складу права читання та запису; політики згоди адміністратора Microsoft можуть блокувати корпоративні облікові записи.

## 4. API після активації передпускове середовище

Усі запити у контурі `ladePoort('cloud')`. Не приймають передані з оглядача `owner`, `ruimte`, bearer або будь-який довільний API host.

- `POST /api/owner/cloud/integrations/v1/accounts/list` -> перелік метаданих (жодних маркерів доступу).
- `POST /api/owner/cloud/integrations/v1/accounts/start` -> `{provider, mode}` -> офіційний `url` і `flowId`.
- `GET /api/owner/cloud/oauth/m4/callback?state=...&code=...` -> повторна перевірка сеансу та простору, одноразове сховище PKCE, перевірка віддалена тотожність, 303 назад у Cloud.
- `POST /api/owner/cloud/integrations/v1/accounts/:id/rename` -> `{label}`.
- `POST /api/owner/cloud/integrations/v1/accounts/:id/disconnect` -> `{confirm:true}`, локальне блокування + спроба віддалене відкликання.

Відсутні API виконання MOVE/COPY через клієнтська частина; M2/M3 транспортний код ще не ввімкнено до приймання на живому середовищі. Маркер доступу-посередник обміну готовий як залежність, але контур фонового фонового виконавця повинен перевіряти `owner+space` із PostgreSQL завдання, а не довіряти фоновому AsyncLocalStorage типово.

## 5. Принципи роботи в кількох оглядачах / вкладках

- Під'єднання та відкликання доступу записані на сервері та стають видимими іншим пристроям при наступному опитуванні.
- `BroadcastChannel('tsv-cloud-accounts-v1')` пробуджує вкладки того самого origin; між піддоменами цей канал не діє — потрібен спільний серверний стан і періодичне опитування або подальший SSE.
- Конкретний активний обліковий запис не записують у загальний browser localStorage і **не** синхронізують як глобальний для всіх. Для різних вкладок — `sessionStorage`, для задач фонового виконавця — явний account id у серверне завдання.
- Зміна OAuth у будь-якій вкладці знедійснює власні показані дані після наступного серверне оновлення. Довготривалі операції при відкликанні дозвіл мають зупинятися після повторної перевірки права.

## 6. Жорсткі перешкоди перед full-випуск

1. Зареєстровані постачальницькі OAuth apps та server секрети, успішні код уповноваження/PKCE зворотний виклик, реальні 2 облікові записи одного постачальника та робочий+особистий одночасно.
2. Box конфіденційний OAuth без удавання вузьких обсяги повноважень; перевірка найменші привілеї, адмін-консенсу для Microsoft, оновлення/відкликання per постачальник; реальна ротація Сховище шифрування key.
3. Nextcloud Login Потік v2 із вихідний трафік/SSRF/DNS-переприв'язування захистом, S3 IAM/role облікові дані без довільних access ключі у оглядачі; ці майстри **НЕ написані** в M4.
4. Реальне увімкнення фоновий режим фоновий обробник, відновлення передавання великих файлів, COPY/MOVE Наскрізні для всіх заявлених постачальників. Conditional ВИДАЛИТИ, аварійне завершення/узгодження; M2/M3 наразі не працюють у робоче середовище.
5. Реальні права спільного доступу постачальника із зазначенням терміну/ролі/відкликання і версії з відновлення; повна перевірка Universal Файл Workspace.
6. Передпускове середовище PostgreSQL міграція 0119 + ключ management/RLS test; Node.js 24+ full перевірка типів і складання, настільні та мобільні пристрої та 2 оглядачі/2 вкладки/2 пристрої Наскрізні.
7. Визначити остаточний список підтримуваних постачальників. Не можна позначати як «під'єднання доступне» ті, у яких немає повноцінного API/початкове ознайомлення.
8. Звірка з **найновішою** робоче середовище base. Наша база — 20261027-212158; якщо вже є пізніший випуск, спочатку тристороннє злиття.
