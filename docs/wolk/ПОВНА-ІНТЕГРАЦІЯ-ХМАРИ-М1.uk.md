# Повна інтеграція Хмари · M1 (розробка, НЕ випуск)

**Дата:** 2026-10-28. **База:** `mijn-ruimte-20261027-212158.tar.gz` — *інтеграційний кандидат*, НЕ доказ встановлення. Встановлена версія може відрізнятися. **Випуск пропускний бар'єр:** `BLOCKED_PENDING_FULL_PROVIDER_ACCEPTANCE`. Цей документ доповнює `CLOUD-RELEASE-CONTRACT-FULL-INTEGRATION-20261028.uk.md`.

## Що написано в коді

- `shared/cloud-integratie-contract.ts`: стабільні ідентифікатори файлів/просторів/облікових записів, 16 дій, типи результатів (`native`, `gateway`, `needs-consent`, `forbidden`, `unavailable`, `temporarily-unavailable`), правила доступності, білий список чинного Cloud-native 6 MiB та закриття при збої план операції.
- `shared/cloud-aanbieder-register.ts`: строгий реєстр перехідників постачальників; не дозволяє двічі реєструвати постачальник та не читає між різними просторами.
- `backend/cloud-integratie-google.ts`: актуальний Google Drive `files.get` через наявний B+ дозвіл та наявний зріз стану облікових записів; маркер доступу не повертається користувачеві; метадані ACL береться з Google під час кожного запиту; час очікування 12 s, без несанкціонованих редиректів.
- `backend/cloud-integratie-register.ts`: справді під'єднано лише Google Drive для live огляд; інших перехідників не фальсифіковано.
- `backend/cloud-integratie-routes.ts`: нові **лише для читання** POST маршрути `status`, `google/file/capabilities`, `transfer/plan`.
- `backend/cloud-platform.ts`: мінімальна інтеграція маршрутів у **вже наявний** `ladePoort('cloud', authorize, ...)`.
- `tests/eenheid/cloud-integratie-contract.test.ts`: автоматичні перевірки політик, помилкових дозволів, ізоляції, MOVE, MIME, 6 MiB.

**Жодної зміни** у `package.json`, OAuth, міграціях, Identity, UI, CanonicalChrome, SSH, розгортанні, платіжних функціях. Новий Cloud UI **не активовано**.

## Чого НЕ реалізовано (не можна називати готовим)

1. Робочі OAuth-з'єднувачі OneDrive, SharePoint, Dropbox, Nextcloud, Box, S3 і GitHub у Cloud; корпоративні політики й орендар-згода.
2. Повний Cloud-native файловий драйвер: чинний Quick Capture має обмеження **6 MiB** і не еквівалентний повноцінному сховищу.
3. Потоковий фоновий обробник передачі між постачальниками, довговічні передавання завдання, дедуплікація й ідемпотентність, delete-after-перевірка.
4. Питомий/шлюз спільний доступ та безпекове доведення ізоляція/ACL/відкликання.
5. Universal Файл Workspace як фактичний єдиний редактор/переглядач для всіх джерел; попередній перегляд у єдиному API навмисно **вимкнено**.
6. Реальна перевірка в авторизованому Google account, робоче середовище Node24 build, постачальник Наскрізні. Нові API маршрути не тестувалися через справжню сеанс; unit-тести перевіряють лише чисту логіку.

## Наявні серверні маршрути (НЕ клієнтська частина)

```text
POST /api/owner/cloud/integrations/v1/status
POST /api/owner/cloud/integrations/v1/google/file/capabilities
  body: { "accountId": "<connected-account-id>", "fileId": "<google-drive-file-id>", "tabContext": "<existing-session-context>" }
POST /api/owner/cloud/integrations/v1/transfer/plan
  body: {
    "mode": "copy",
    "source": { "provider": "google-drive", "accountId": "...", "fileId": "...", "space": "prive" },
    "target": { "provider": "cloud-native", "accountId": "own", "space": "prive" },
    "tabContext": "<existing-session-context>"
  }
```

Третій маршрут завжди повертає `decision: blocked` і причину `TRANSFER_EXECUTOR_NOT_READY`, навіть якщо всі вхідні права правильні. **POST виконання передачі не існує**. Це свідома вимога безпеки, а не готовий бізнес-сценарій. Клієнт не має відображати кнопку «Перенести» як активну.

## Наступний етап M2

1. Звірити копію з актуальним розгорнутий Git SHA / архівом. `Tarasevych/hub` у доступній гілці `voornaamst` не містить `package.json`; GitHub-фіксація змін `bdb63c9d...` в ньому не знайдений. Не форсувати злиття в цей репозиторій без підтвердження джерела істини.
2. Узгодити атомарний процес життєвого циклу переносів у PostgreSQL: `plan → authorize → stream → verify → commit`, `idempotency` з унікальним індексом і повторним ACL при кожній зміні. План повинен зберігати власник + space + provider/account/resource + etag, без маркерів доступу.
3. Під'єднати Google → власний Cloud лише після усунення 6 MiB/форматного обмеження або чіткого спеціального bounded потік. Спочатку COPY. MOVE — лише після підтвердження copy і delete-after-перевірка.
4. Додати уніфіковані перехідники і contract-тести Microsoft Graph (Personal/Business/SharePoint), Dropbox, Nextcloud/WebDAV+OCS, Box. Кожен з власною моделлю OAuth/ACL/посторінкова розбивка/відновлюване вивантаження/обмеження частоти запитів.
5. Реалізувати ізольований QA тестовий зразок для дозвіл negative-tests. Перенести наявний Mail/Drive document переглядач у спільне ядро без регресій.
6. Після затвердження всіх заявлених постачальників — впровадити `/overzicht` та інтегроване UI, прогнати повні наскрізні, передпускове середовище та відкочування; сформувати єдиний новий UITROL-VERSIE.
